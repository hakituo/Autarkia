- **去掉「角色每句话都报备自己在做什么」的提示引导**
  - **背景**: 角色日程接入主对话后，角色几乎每条回复都带一句自己的当前状态
    （实测同一段会话里连续出现「我这边刚起，洗漱去」「我这刚起，去刷牙」
    「我牙还没刷完」「我真的去刷牙了」「我这边在做葱油饼」），像是每轮在向用户报备行程。
  - **根因**: 不是日程数据本身的问题，而是**三段提示文案在主动推模型去说**，
    三段都进同一条 user 消息的【环境】块：
    1. `reply_hints._SOFT_DELAY_REPLY_TEMPLATE`（主因）原文写「可以轻轻带一句自己刚才在做什么」。
       触发它的 `SOFT_REPLY_DELAY_ACTIVITIES` = 全部活动**减去**
       `{sleeping, napping, waking_up, overslept_recovery, studying, peer_chat}`，
       即发呆/刷手机/看书/游戏/做饭/家务/散步/三餐/逛街/洗澡全在内。
       按 2026-09-20 的实际日程算，aveline 清醒 838 分钟里 **743 分钟（89%）** 落在该集合，
       也就是这段时间内**每条回复**都带这句邀请；yeye 为 74%。
    2. `reply_hints._PLAN_TRANSITION_TEMPLATE` 是强制语气：「这条回复里必须自然体现
       你已经意识到这个时间点，不要机械报时，也不要完全不提」。配合
       `plan_transition_notice_seconds=300`，而日程槽位背靠背、平均 34–35 分钟一槽、
       每天 24–27 槽，等于每天约 2 小时泡在这个强制提及窗口里。
    3. `character_daily_context` 每轮注入 `daily_activity=做饭` / `planned_time=08:56-09:30`
       这类 key=value 裸事实，主聊天侧没有任何使用约束。
       `prompt/README.md` 只写「不要求角色每轮报备」，是文档约定，代码里没有东西保证它。
  - **修复**: 统一改成「只给事实，不给引导」，并在原来给引导的位置换成反向约束。
    - `_SOFT_DELAY_REPLY_TEMPLATE`：「可以轻轻带一句自己刚才在做什么，但不要解释得很机械」
      → 「不要主动交代自己在做什么」；活动描述由「你刚刚在 X」改为「你现在在 X」。
      延迟事实（`隔了大约 N 秒`）保留——它解释的是回复间隔，不是让人报备。
    - `_BUSY_INTERRUPTED_PERSONA_HINT` / `_BUSY_INTERRUPT_TEMPLATE`：删掉
      「可以提一句自己在做什么」，换成「不要主动交代自己在做什么」。
      前者改为带 `{activity_verb}` 占位符的模板，`build_busy_interrupt_hint()` 的空列表分支
      同步补 `.format()`——漏掉会把占位符原样送进 prompt。

      改为「提不提这件事由你按当前聊天氛围决定，不提也可以」，顺延/收尾两个选项保留。
      睡前的收尾倾向（`build_plan_transition_hint()` 里对睡觉类活动的追加说明）保留，
      否则角色会直接无视睡觉时间继续聊。
    - **`character_daily_context` 本身没有改**：那块被
      `tests/scripts/personas/verify_character_daily_prompt_context.py` 的 coaching_phrase
      断言守着（`"回答时" / "不要" / "可以提及" / "按这块信息不存在"` 都不许出现），
      是刻意的「事实块不带回复指导」设计，往里面加「不要…」会直接踩护栏。
