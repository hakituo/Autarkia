- **修复安卓端「开着组网却一直走公网域名」**
  - **背景**: 用户反馈：手机连着 Tailscale 组网时，客户端仍连公网域名；只有在设置页把「手动锁定」填成组网点对点地址时才会走组网。排查确认是自动裁决链上两个独立缺口叠加：组网槽位没被填过，以及退到公网后再也没有事件能把通道升回组网。
  - **根因**:
    - 组网槽位默认空串且没有任何自动填充：AppPreferences.DEFAULT_VPN_URL 为空，写入点只有设置页手填与设置导入，EndpointResolver.resolve() 里 `if (vpn.isNotEmpty() && probe(...))` 会整档跳过。手动锁定位则会在 resolve() 第一步直接 return，压根不探测，所以「只有手动指定才走组网」。
    - 槽位迁移不认组网地址：旧的单一 backendUrl 落在组网段时只被写进 activeUrl 缓存，第一次裁决就被公网域名覆盖。
    - 退到公网后无法回退升级：EndpointResolver 只有事件型触发，而「Tailscale 连上 / 打洞完成」不产生 ConnectivityManager 回调（默认网络恒为 VPN 网络，transportOf() 恒为 other，被 onCapabilitiesChanged 的 transport 去重挡掉）；公网通道一直可用则 WebSocket 不失败、resolveOnFailure() 也不触发，通道永久停在公网。
  - **修复**:
    - 新增 BackendAddressRules（纯函数，无 Android 依赖）：把「私网 / 组网 / 公网」三类地址判据收敛成唯一实现，消除 EndpointResolver 与 AppPreferences 各自维护一份同判据的分叉风险。组网段按 CGNAT 100.64.0.0/10 判定，与私网判据互斥。
    - AppPreferences 槽位迁移 V2：旧地址落在组网段时一并认进 vpnUrl 槽位。
    - AppPreferences 新增一次性迁移 V3（promoteVpnSlotIfNeeded）：vpnUrl 为空时，把「手动锁定 / 上次裁决结果」里的组网地址复制进 vpnUrl 槽位；不修改手动锁定本身，用户清空该格即可进入自动模式。
    - EndpointResolver 新增周期重探（startPeriodicReprobe，5 分钟）与前置判断 hasBetterCandidate()：只在「存在更优候选」时才真的发起探测，覆盖「候选可用性变化但不产生网络回调」的场景，使通道能从公网自动升回组网或局域网。

  - **背景**: 承接同日「聊天历史纳入跨系统同步」。记忆与聊天同源：两个系统各自累积加权记忆、短期记忆、会话列表与指纹索引的持久状态，整文件「谁新用谁」会丢掉另一边的积累——切系统后角色对另一台机器上发生的事一无所知。本次把 companion_data/*/memories/ 纳入同步，并针对三种落盘形状给出统一的条目级并集规则。
  - **根因**:
    - 记忆文件是「各自累积、整份落盘」，两端都改过时没有可用的裁决依据：覆盖任何一边都等于丢记忆
    - 记忆有三种落盘形状（顶层数组 / 含条目数组的对象 / 「指纹 → 条目」映射），单一合并规则覆盖不了
    - 上一版只有聊天用得上合并策略，清单项与分派入口都还没有承载「第三类合并」的位置
  - **修复**:
    - scripts/sync/learning_data/items.py 新增 MERGE_MEMORY 合并策略与 memories 分组：*/memories/**/*.json（通配符已能覆盖散落在 memories 根下的 sessions.json / persistent_states_*.json，无需额外清单项）
    - 新增 scripts/sync/learning_data/memory_merge.py：按形状做条目级并集——顶层数组按条目 id 取并集（缺 id 用内容指纹）；含条目数组的对象先并列表、其余标量键取更新的一方（如 last_updated 取更晚的）；「指纹 → 条目」映射按键取并集、同键取 updated_at 更新的一份
    - 「更新」的判据统一为条目里 timestamp / last_access_time / updated_at / created_at / last_updated 的最大值（数字左补零成定长字符串，与时间串混排不会报错），并列时用规范化 JSON 兜底，保证结果与合并顺序无关、对已合并结果幂等
    - scripts/sync/learning_data/chat_merge.py 的 union_bytes 增加 memory_union 分派（并清掉此前未被引用的 UNION_OF 常量）
    - scripts/sync/README.md 补 memories 分组与三种形状的合并规则，并写明取舍：只有一端改过时仍走普通复制（删除正常传播），只有「两端都改过」的窗口里被单方删除的条目会被补回
    - 新增 tests/unit/test_learning_data_sync_memories.py（9 例）覆盖三种形状、同 id 取更新、顺序无关与幂等、非法 JSON、扫描排除 backups、两端都改走 MERGE、执行后收敛为一致

  - **备注**:
    - 并集只发生在「两端都相对基线改过」时，因此删除在常规路径上仍会传播；只有两端都改过的窗口里，被单方删除的条目会被另一边的版本补回来——刻意取舍：宁可能多留一条，也不丢记忆
    - 合并后记忆文件会被规范化重写（ensure_ascii=False + 两空格缩进），JSON 语义不变，格式可能与原写入端略有差异
    - 派生数据（记忆索引、缓存）不参与同步，清单只覆盖 memories 下的 JSON 真源
