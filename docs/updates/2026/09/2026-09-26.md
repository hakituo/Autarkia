- **start_scripts 批处理启动器：消除 chcp + 非 ASCII 引起的 cmd 解析漂移与块内括号陷阱**
  - **背景**: 用户反馈 `start_scripts/start_qq_bot.bat` 双击启动不了，报错把命令截断成 `'ain.py' is not recognized`、`'ASE_DIR' is not recognized`、`'根目录（main.py' is not recognized` —— 显然是脚本自身的行被读错位，与 NapCat / adapter 无关。
  - **根因**:
    - cmd.exe 按“当前控制台代码页”逐行解码 .bat；文件含多字节（非 ASCII）字符时读取位置漂移，把后续行截断，于是 `main.py` 读成 `ain.py`、`BASE_DIR` 读成 `ASE_DIR`、中文行读成半截。
    - 对照实测 4 种方案：文件内 `chcp 65001`、UTF-8 with BOM、GBK 编码**均仍漂移**；只有内容为纯 ASCII 时与代码页无关、彻底稳定（`chcp 65001` 行可保留，供子窗口 Python 中文日志显示）。
    - 另有两个独立缺陷：命令块 `if/else (...)` 内 `echo` 文本含 ASCII 右括号 `)` 会提前闭合该块、吞掉后续 echo；块内 `::` 注释实为标签写法，会破坏 `if` 块，块内必须用 `rem`。
  - **修复**:
    - 6 个受影响批处理全部改为纯 ASCII 文本（start_qq_bot / start_demo / start_services / start_multi_qq_bot / start_qq_official / start_rushuang_napcat）：中文提示与注释译为英文，块内 `::` 改 `rem`，块内 `echo` 去掉 ASCII 括号。逐行核对 diff，只动文本、不动命令与逻辑与行序。
    - start_frp.bat / start_web.bat / start_frp.ps1 经字节级核查本就纯 ASCII，无需修改。
    - start_pet.bat 判定为不同类问题并列入例外未改：其第 43 行 `echo ... (%RETRY_COUNT%/%MAX_RETRIES%)` 的 `)` 是“承重括号”，提前闭合第 22 行 `if %errorlevel% neq 0 (` 恰好让 `goto CHECK_PORT` 跳出块外、运行期才展开变量；若只删括号，第 45 行会在解析期展开成 `if lss goto CHECK_PORT` 报 `goto was unexpected at this time`（exit=255）。
    - 新增通用检查器 `tests/scripts/startup/verify_start_scripts_batch_safety.py`：静态项（纯 ASCII / 无 BOM / 块内 echo 无括号 / 块内无 `::` / 括号收尾闭合）+ dry-run 副本检测漂移症状串（`is not recognized`、`was unexpected at this time` 等），start_pet.bat 按白名单跳过 dry-run。
  - **验证**:
    - `venv_cpu\Scripts\python.exe tests\scripts\startup\verify_start_scripts_batch_safety.py：start_scripts 下 9 个 bat 静态检查全 PASS，dry-run 无漂移症状。`
    - `反向验证：把 HEAD 修复前内容喂给检查器，start_multi_qq_bot（150 非 ASCII 字节）/ start_services（465）/ start_demo（1674 + 行 226）均被 CAUGHT，start_pet.bat 因例外白名单 NOT CAUGHT（符合设计）。`
