## 2026-09-07（周一）

- **peer chat 增加双方在线门禁，对方 QQ 未登录时不再自言自语**
  - **背景**: Ling（ling，QQ 123456789）的 QQ 完全没开，日志里仍出现「七濑 Aveline | 发送 -> 私聊 (123456789)」，Aveline单方面发完台词后对方收不到也不回，但 today_peer_chat_count 与 last_peer_chat_ts 照常被消耗。
  - **根因**:
    - CharacterDailyEngine 的 peer chat 触发链路（_maybe_trigger_peer_chat → should_trigger_peer_chat → execute_peer_chat → trigger_via_scheduler）只看虚拟作息活动、时段、间隔与概率，完全没有「对方是否真的接入」这一层校验
    - QQConnectionResolver.ALWAYS_ON_ROLE_IDS 包含 aveline/ling，静态 multi_qq_config 兜底会为它们生成连接，因此 _get_multi_qq_connections() 恒 >= 2，系统一直认为「双 QQ 模式成立」
    - PeerChatScheduler 里唯一的连接门禁 can_send_proactive_message() 对常驻白名单角色恒为 True，且它依赖的 QQAdapter 注册表在 adapter 独立进程运行时在后端进程里恒为 0，拿不到真实在线证据
    - 发送走发起方自己的 NapCat 连接直发对方 QQ 号（peer_{target_qq_id}），QQ 对离线账号照样投递离线消息，所以日志显示发送成功、计数照常 +1
  - **修复**:
    - core/services/active_care/core/qq_connection_resolver.py：新增 get_live_qq_role_ids()（扫描 WebSocket 连接，只认带角色前缀的 client_id，如 qq_aveline_private_10001）、has_real_role_connection()、check_peer_chat_participants_online()
    - check_peer_chat_participants_online() 在无法识别任何角色的环境（旧客户端不上报 role_id）放行，避免误伤老部署
    - core/services/character_daily/engine_peer_chat_support.py：trigger_via_scheduler 在生成剧本前做双方在线门禁，被拦截时记 PEER_CHAT 诊断日志并返回 False（不调用决策 LLM、不计次）
    - core/services/active_care/peer_chat/peer_chat_scheduler.py：_check_and_trigger_for_role 的 peer 候选循环、提醒分工协商、主动关怀时段分工协商三处均加上同一门禁
    - 新增配置 dual_role.peer_chat_require_live_connections（默认 true，config/settings_life.py + config/yaml/app.yaml），可一键退回旧行为
  - **验证**:
    - `venv_core\Scripts\python.exe tests\scripts\active_care\verify_peer_chat_live_connection_gate.py（PASS）`
    - `venv_core\Scripts\python.exe -m pytest --ignore=... --deselect ... -q（624 passed, 18 skipped）`
    - `venv_core\Scripts\python.exe -m ruff check <改动文件>（All checks passed）`
  - **备注**:
    - 门禁依据是后端的 WebSocket 连接（client_id 带 role_id），不是 QQ 好友在线状态——QQ 协议本身拿不到好友在线状态
    - 若 adapter 与后端同进程，QQAdapter 注册表命中也会被视为在线，两条证据取或
    - 需重启后端生效；Ling QQ 上线后互聊自动恢复
