- **Android 上传改为 chunked 长度界定，修复 multipart 被截断**
  - **背景**: 手机端（经 Cloudflare Tunnel）上传图片偶发失败，报错只有一个没有上下文的状态码。先查后端访问日志定性：全量只有 200 / 404 / 422，从头到尾没有出现过 400；手机的 chat/message 35 次全部 200，而手机的 media/upload 一次都没有 —— 上传请求根本没到后端，报错发生在 Cloudflare 边缘。
  - **根因**:
    - `FileUploadManager` 的流式 RequestBody 直接把 `OpenableColumns.SIZE` 元数据当 `contentLength()`。该值由 ContentProvider 提供，可能与真实字节数不符（媒体库行过期、云相册返回的是缩略图大小、部分 provider 直接给 0）。
    - 元数据偏小时 MultipartBody 会算出偏小的 Content-Length。走隧道时 OkHttp 用 HTTP/2，帧层不再按长度校验，多出的字节照发；而 Cloudflare / uvicorn 只按声明长度收，multipart 被截断，FastAPI 拿不到 file 字段。
    - 复现确认：声明 8MB 但 Content-Length 只报 4MB 时，后端稳定返回 422，响应体为 `{"detail":[{"type":"missing","loc":["body","file"],"msg":"Field required"}]}`。
  - **修复**:
    - `contentLength()` 改为返回 -1（长度未知），让 OkHttp 改用 chunked，长度由分块界定，不存在截断可能。压缩分支仍走已知长度的 ByteArray，不受影响。
    - 上传失败时把响应体前 300 字符带进异常信息，后端 detail 与 Cloudflare 的说明不再被丢掉，下次失败能直接看到原因。
  - **验证**:
    - `静态核对：括号配对 {} 36/36、() 124/124；全仓仅剩 1 处 `contentLength()` 且不再引用 fileInfo.size；`IOException` 已导入；全 App 只有 1 处构造 MultipartBody（Android 例外，待编译验证）`
  - **备注**:
    - 同轮排查的隧道抖动（对话出 530）是独立问题，未在本次改动：实测同一时刻连打 20 次 /api/v1/health 全部 530，本机直连 20 次全部 200；稍后再打 12 次又全部 200，说明是 connector 与边缘之间的间歇性掉线，而不是后端故障。
    - 出口 IP 不稳定是主要嫌疑：本机 10 分钟内先后经不同服务探测到两个不同公网 IPv4，而隧道 connector 注册时记录的是第三个，长连接被重 NAT 掉就会整段 530。
    - 待用户确认的加固项（本轮未做）：升级 cloudflared（当前 2025.8.1，官方提示升到 2026.9.3）、增加连接冗余、端上对瞬时 5xx 做重试。
    - 顺带发现的缺口，本轮未改：`getFileInfo` 取不到 SIZE 时返回 0，`validateFileSize` 会直接放行，10MB 上限形同虚设；改 chunked 后这个缺口不再被 Content-Length 间接挡住，建议后续单独收紧。
