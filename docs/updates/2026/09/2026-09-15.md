- **安卓端发任何消息 AI 都不回复：gzip 请求体中间件伪造断连，SSE 流在第一个 chunk 前被取消**
  - **背景**: 安卓 App 发任何消息都没有回复；同链路 Web 端与 curl 明文请求一切正常。后端日志只到 `[AvelineService] [stream_conversation] ...` 和 Active Care 重置，之后既没有 `Start stream_generate_response`、也没有任何报错，`POST /api/v1/chat/message` 还返回 200。
  - **根因**:
    - `core/middleware/gzip_request.py` 的 `_single_body_receive()` 在第二次被调用时直接返回 `{"type": "http.disconnect"}`
    - uvicorn 的 HTTP 协议上报 ASGI `spec_version = "2.3"`（< 2.4），Starlette 的 `StreamingResponse` 在该分支下会额外起一个 `listen_for_disconnect` 协程不断 `await receive()`，一拿到 `http.disconnect` 就取消整个流式响应
    - 安卓 streaming client 有 gzip 请求体拦截器（body ≥ 1024B 就压缩，聊天请求带 `history_override` 必然命中）→ 每次都在第一个 chunk 产出前被掐断，生成器抛 CancelledError（继承自 BaseException，`except Exception` 兜不住），所以连错误日志都没有
  - **修复**:
    - `_single_body_receive(payload, upstream_receive)`：首次返回解压后的完整 body，之后**交还给上游真实 receive**（未断连时挂起，真断连时才返回 http.disconnect），不再伪造断连
    - `GzipRequestBodyMiddleware.__call__` 把原始 `receive` 传进去
  - **验证**:
    - `.tmp/verify_gzip_fix.py`（venv_core python）：复刻 Starlette 2.3 的断连监听语义，修复前发出 0 个 chunk、修复后 3 个
    - 真实服务器对照：明文 body → 正常 SSE；`Content-Encoding: gzip` body → 修复前返回完全为空

    - QQ 通道的历史来自后端记忆池，经 sanitize_history_messages 给每条历史补 [MM-DD HH:MM] 时间戳前缀，模型能看到每条消息的发生时刻。
    - 安卓通道走 history_override，客户端只传 role/content 纯文本，build_conversation_history 的 override 分支直接透传、完全绕过了 sanitize_history_messages，历史消息没有任何时间信息。
    - 结果：上下文里只有最后一条 user 消息前缀的'当前时间'，历史里的'我吃饭了'没有任何时刻标记，模型默认把它当最近发生，于是继续追问'吃完没有'。
  - **修复**:
    - 安卓端 HistoryOverrideMessage 增加 timestamp 字段（epoch 毫秒），ChatRepositoryImpl 流式/非流式两处上传历史时带每条消息的时间戳。
    - 后端 routers/v1/chat.py 解析 history_override 时保留 timestamp，并把毫秒归一化为秒，与后端记忆池秒级时间戳一致。
    - core/agents/chat_agent_components/context.py 的 override 分支保留 timestamp 并复用 sanitize_history_messages 补 [MM-DD HH:MM] 前缀，与 QQ 路径完全对齐；旧客户端不带 timestamp 时原样透传，向后兼容。
  - **验证**:
    - `venv_core 运行 tests/scripts/prompt/verify_timestamp_injection_parity.py：override 历史带 timestamp 时补出 [MM-DD HH:MM] 前缀且正文不被改写；旧客户端不带 timestamp 时历史原样透传；HTTP/QQ 两通道均仍注入当前时间。`
    - `venv_core 运行 Core CI 同款 pytest 命令：985 passed, 18 skipped。`
    - `ruff check 本次改动文件全部通过。`
    - `安卓端改动（MessageRequest.kt / ChatRepositoryImpl.kt）按约定不在沙箱跑 Gradle，待用户在 Android Studio 编译验证。`
  - **备注**:
    - 时间戳格式沿用 QQ 的 [MM-DD HH:MM]，sanitize 会先剥掉历史里已存在的同类前缀再补，不会叠加。
    - 该机制只影响模型对消息先后与时距的判断，不影响聊天记录本身展示。
