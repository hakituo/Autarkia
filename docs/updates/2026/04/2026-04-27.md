- **🔴 修复：DeepSeek v4-pro 思考模式下 content 被 `<think` 标签吞掉导致每次都触发 retry**：
  - **根因**：DeepSeek v4-pro 思考模式下，`content` 字段中会冗余包含 `<think/>...</think/>` 标签，而 `streaming.py` 的 `pending_text` 缓冲逻辑遇到 `<think` 就进入 `in_think=True` 状态，导致所有后续 content 被当作 `thought_content` 吞掉，`current_response_content` 为空，触发二次 API 调用
  - **修复1**：在 content chunk 进入 `pending_text` 前，先用正则清理冗余的 `<think/>` 和 `</think/>` 标签（因为思考内容已通过 `reasoning` 字段正确分离）
  - **修复2**：`pending_text` 中的 `<think` 标签处理逻辑增加判断——如果已有 `thought_content`（说明思考内容已通过 `reasoning` 字段接收），则直接跳过冗余的 `<think/>...</think/>` 块，不进入 `in_think` 模式
  - **效果**：消除每次对话的二次 API 调用，节省 token 和延迟
  - **验证脚本**：`tests/scripts/test_think_tag_fix.py`
