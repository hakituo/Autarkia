## 2026-04-09（LLM模块解耦重构）

### 问题：`openai_client.py` 职责过于混杂

- **问题表现**：
  1. 单文件 743 行，承担了 API 通信、消息规范化、错误处理、流式解析、日志记录等多种职责
  2. API 调用日志与业务逻辑强耦合
  3. 流式响应解析代码重复
  4. 继承设计不合理（`AvelineClient` 只是改了默认参数）

- **重构内容**：
  1. `api_monitor.py` - API调用日志模块：计数、调用栈追踪、日志输出
  2. `message_utils.py` - 消息规范化模块：角色映射、消息规范化、Payload构建
  3. `error_handling.py` - 错误处理模块：SSL/网络错误判断、瞬时错误检测、错误格式化
  4. `stream_parser.py` - 流式响应解析模块：SSE解析、content/reasoning提取
  5. `openai_client.py` - 精简为核心逻辑：只做 HTTP 通信、会话管理、重试编排

- **重构后效果**：
  - `openai_client.py` 从 743 行精简到 ~320 行
  - 职责清晰分离，便于单独测试和维护
  - 新增模块可独立复用

## 2026-04-09（错误日志独立记录，不经过BERT分析）

### 需求背景
主程序发送报错消息时，该消息会被 BERT analyze 进行语义分析，然后落盘到用户可见的历史记录中。用户希望：
1. 报错消息落盘到 `logs/YYYY/M/D/error.log`，不污染用户历史和 companion_data
2. 报错消息不经过 BERT 语义分析

### 修改内容

#### 1. 新增 `core/services/error_log_store.py`
- 专门记录系统错误的模块，线程安全
- 错误日志存储在 `logs/YYYY/M/D/error.log`（与 server.log、xiaoyou_main.log 并列）
- 每条错误记录包含：
  - `error_id`: 唯一标识
  - `conversation_id`: 会话ID
  - `user_message`: 用户原始消息
  - `error_message`: 错误信息
  - `error_code`: 错误码
  - `error_details`: 额外错误详情
  - `model_hint`: 模型提示
  - `stack_trace`: 堆栈跟踪（截断至2000字符）
  - `source`: 错误来源（如 stream_orchestrator）
  - `timestamp/datetime`: 时间戳

#### 2. 修改 `core/services/aveline/stream_orchestrator.py`
- 在错误处理分支中集成错误日志记录
- 错误消息正常 yield 发送给客户端
- 但不保存到正常历史记录，直接 return 跳过

### 关键代码逻辑
```python
# stream_orchestrator.py 中的错误处理
if isinstance(chunk, dict) and chunk.get("type") == "error":
    # 记录到 logs/YYYY/M/D/error.log（不经过BERT）
    get_error_log_store().append_error(...)
    # 正常返回错误事件
    yield evt
    # 不保存到用户历史，直接返回
    return
```

### 行为变化
- **Before**: 错误消息 → 保存到用户历史 → BERT分析
- **After**: 错误消息 → 保存到 error.log → 直接返回用户历史

### 日志文件位置
```
logs/
└── 2026/
    └── 04/
        └── 09/
            ├── server.log       # 服务器日志
            ├── xiaoyou_main.log # 主程序日志
            └── error.log        # 错误日志（新增）
```

### 测试文件
- `tests/test_error_log_store.py`: 错误日志存储测试

## 2026-04-09（Active Care 决策/表达分离与思维链防泄露）

### 问题背景
- Active Care 在部分推理模型下出现“调度决策文本”和“角色回复文本”混杂，导致主动消息可能把内部推理或指令草稿直接发给用户。
- `prompt_builder.py` 注入了过多后台状态信息，弱化了角色自然表达空间。

### 本次改动
- `core/services/active_care/decision.py`
  - 决策阶段改为“纯调度”模式：只输出 `should_send / next_check_seconds / intent / thought` 的 JSON 决策。
  - 不再在决策阶段要求角色化输出聊天文案，降低推理模型输出链路污染风险。
  - 保留并强化时间/画像相关约束语义字段，兼容现有诊断脚本。
- `core/services/active_care/executor.py`
  - 新增主动消息安全守卫：识别“提示词/思维过程泄露型输出”（如“我需要：…遵守人设…”）。
  - 命中后优先提取可直接发送的一句短消息；提取失败时回退到已有非复读兜底文案，避免把内部推理发到前台。
- `core/services/aveline/service.py`
  - 主动消息 `response_done` 包不再携带 `thought` 字段，避免内部思考从 websocket 透传到前端。
- `core/services/active_care/prompt_builder.py`
  - 收敛后台上下文注入范围：仅在相关场景注入 bio/food/study 大块上下文，减少“上帝视角”污染。

## 2026-04-09（DataOps BERT cache miss 启动卡顿优化：批量向量推理）

### 问题背景
- 主程序启动时若命中 `Computing embeddings (cache miss)...`，会对定义词逐条做 ONNX 推理，导致初始化阶段出现明显停顿。

### 本次改动
- `core/services/data_ops/bert_runtime_mixin.py`
  - 新增 `_get_text_embeddings_batch`，将文本按批次送入 tokenizer + ONNX `pooler_output`，减少逐条推理开销。
  - `_compute_embeddings_for_dict` 从单条循环改为批量取向量后再聚合原型向量。
  - `intent_examples` 首次构建改为批量嵌入后归一化，保持语义逻辑不变。
  - 保留异常回退路径：批量失败时自动回退到单条推理，确保兼容性。

- `venv_core\Scripts\python.exe -m mypy core\services\data_ops\bert_runtime_mixin.py`
