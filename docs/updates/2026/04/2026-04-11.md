## 2026-04-11（视觉识别架构优化：VL模型直接回复 + 默认切云端）

### 改动背景
- 原先 SiliconFlowClient 的视觉处理采用两阶段：VL模型描述图片 → LLM根据描述回答
- 两阶段处理存在严重问题：替换整个消息链，导致人设丢失、对话历史丢失、Prompt缓存全废
- 视觉模型 Qwen3-VL-235B 本身就是 Thinking 模型，推理能力足够直接回答，无需再过一层 LLM
- VisionModule 默认使用本地 Qwen2-VL-2B，能力有限且占用本地资源

### 本次改动
- **SiliconFlowClient**：两阶段处理改为 VL 模型直接回复
  - `chat()`：检测到图片时，将完整消息链（含人设、上下文、图片）直接发给 VL 模型，一步到位
  - `stream_chat()`：同理，流式输出时直接用 VL 模型，保留完整消息链
  - 删除 `_extract_text_prompt()` 方法（不再需要提取文本给中间 LLM）
  - `_vision_inference()` 简化为直接传入完整 messages，不再构造新的 vision_messages
- **VisionModule 默认配置**：从 `local` 改为 `siliconflow` 云端 Qwen3-VL-235B
  - `integrated_config.py`：vision 默认 provider 改为 siliconflow，model 改为 Qwen3-VL-235B
  - `app.yaml`：同步更新 vision 配置
- **Prompt 缓存兼容性**：所有路径的视觉描述插入位置均在动态部分，不破坏缓存
  - QQ 适配器：`【你看到了一张图片：xxx】` 插入在 user message 开头（消息链末尾，动态部分）
  - SiliconFlow 客户端：完整消息链直接传给 VL 模型，system prompt（静态前缀）保留
  - WebSocket 前端：视觉描述作为独立消息返回，不插入 prompt

### 优势
- 延迟减半（1次API调用 vs 2次）
- 成本减半
- 无信息损失（VL模型直接看原图，不经过描述转述）
- 人设和上下文完整保留（system prompt + 对话历史不丢失）
- Prompt 缓存不受影响

## 2026-04-11（QQ Adapter 连接日志优化：静态状态切换）

### 改动背景
- QQ adapter 连接失败时会不断重复输出错误日志，刷屏控制台
- 用户希望改成静态切换：连接失败只输出一次，直到连接成功才输出一次

### 本次改动
- `clients/bots/qq_adapter_session.py`：
  - 添加 `_connection_state` 属性跟踪连接状态（"connected" / "disconnected"）
  - 连接失败时只在状态从 connected 变为 disconnected 时输出错误日志
  - 连接成功时只在状态从 disconnected 变为 connected 时输出日志
  - 修复 `_conn_issue_notified` 引用错误（应为 `self.adapter._conn_issue_notified`）

### 效果
- 连接失败时只输出一次错误日志，不会重复刷屏
- 连接成功时输出一次成功日志
- 状态变化时才有日志输出，更清晰
