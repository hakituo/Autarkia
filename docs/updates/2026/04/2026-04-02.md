## 2026-04-02（修复 Active Care 话题单调问题）

- 问题描述：
  - 一直围绕"熬夜/睡觉"话题，内容重复没新意
- 问题根因：
  - 去重机制只检查语义相似度，但"熬夜"、"别熬夜了"、"还不睡"等表述不同但意思相同
- 解决方案：
  - **添加话题冷却机制** ([executor.py](file:///d:/AI/xiaoyou-core/core/services/active_care/executor.py#L949-L1056))
    - 新增 `_detect_topic_category()` 检测消息话题类别（sleep/greeting/care）
    - 新增 `_check_topic_cooldown()` 检查是否需要冷却
    - 新增 `_build_topic_diversity_constraint()` 生成强制切换指令
    - 对 "sleep" 类话题：最近5条中有3条同类则触发冷却
    - 冷却时强制要求切换到其他话题（日常、兴趣、陪伴等）
- 关键改进：
  - 避免连续发送多条"熬夜"相关消息
  - 话题多样性显著提升

## 2026-04-02（修复 Active Care 睡眠模式被意外取消的问题）

- 问题描述：
  - 用户说"那我睡了"后，Active Care 仍然每隔1小时发一条消息
  - 用户可能只是随手回了个"嗯哼"，但系统把这当成"用户还醒着"，直接取消睡眠模式
  - 导致凌晨3点、4点还在被消息打扰
- 问题根因：
  - `service.py` 的 `_process_user_response()` 中，用户说晚安后的**任何回复**都会立即取消睡眠模式
  - 没有区分"无意回复"（如"嗯"、"嗯哼"）和"实质性回复"
  - 取消睡眠模式后会更新 `last_user_interaction_ts`，触发新的主动消息循环
- 解决方案：
  - **新增无意回复检测机制** ([service.py](file:///d:/AI/xiaoyou-core/core/services/active_care/service.py#L635-L690))
    - 提前检查：在更新 `last_user_interaction_ts` **之前**先判断是否为无意回复
    - 判断条件：
      - 用户说晚安后 **5分钟内** 回复
      -且回复内容 **≤4个字**
      - 或回复内容在白名单中（嗯、嗯哼、哦、好、行等）
    - 如果是无意回复：
      - **不更新** `last_user_interaction_ts`（不会触发新主动消息）
      - **不取消** 睡眠模式（保持静默）
      - 记录日志：`[提前拦截] 检测到晚安后无意回复`
    - 只有实质性回复才会取消睡眠模式
- 关键改进：
  - 用户说晚安后随手回了个"嗯哼" → 保持睡眠模式，不再打扰
  - 用户说晚安后又发了长消息 → 正常取消睡眠模式（确实没睡）
  - 凌晨时段的被打扰问题应该大幅减少

## 2026-04-02（优化 EmotionStore 情绪历史写盘阻塞）

- 问题描述：
  - `EmotionManager.process_text()` 每次处理文本都会调用 `EmotionStore.add_record()`
  - 旧实现里 `add_record()` 会同步 `open(...).write(...)`，高频对话下会把磁盘 IO 直接压在主链路上
  - 情绪模块虽然轻量，但它在实时对话路径里，持续同步写盘会放大尾延迟
- 问题根因：
  - `core/emotion/store.py` 只有内存缓存，没有真正的异步落盘机制
  - 每条情绪记录都会单独打开文件并立即写入，存在频繁文件句柄操作
- 解决方案：
  - **引入后台批量写盘线程** ([store.py](file:///d:/AI/xiaoyou-core/core/emotion/store.py))
    - `add_record()` 改为只做内存缓存 + 入队
    - 后台线程按用户聚合后批量 `writelines(...)`
    - 新增 `flush()` / `close()`，保证退出前能把队列写完
  - **新增优化验证脚本** ([verify_emotion_store_async_write.py](file:///d:/AI/xiaoyou-core/tests/diagnostics/verify_emotion_store_async_write.py))
    - 用慢写盘桩函数模拟磁盘阻塞
    - 验证 `add_record()` 已不再同步等待写盘完成
- 关键改进：
  - 情绪记录写盘从主线程剥离，实时对话链路更稳
  - 多条记录可合并写入，减少频繁打开文件的 IO 开销
  - 保留 `flush/close` 兜底，降低数据丢失风险

## 2026-04-02（优化启动配置缓存与模型探测缓存）

- 问题描述：
  - `get_settings()` 启动时会重复解析 `app.yaml`，并再次做本地模型自动探测
  - 对话服务虽然进程内只初始化一次，但每次重启后都会重新走一遍 YAML 解析、目录扫描、模型候选探测
  - 在模型目录较大或磁盘较慢时，这部分会拉长启动时间
- 问题根因：
  - `config/integrated_config.py` 缺少跨进程的启动缓存
  - `app.yaml` 读取使用相对路径，缓存前也没有统一的项目根路径解析
  - 模型探测每次都重新扫 `models/llm`、`models/qwen`、`models/voice` 等目录
- 解决方案：
  - **新增启动缓存文件** ([integrated_config.py](file:///d:/AI/xiaoyou-core/config/integrated_config.py))
    - 在 `cache/startup_settings_cache.json` 持久化保存解析后的 `app.yaml` 与模型探测结果
    - 使用版本号、文件签名、环境变量快照做缓存校验
  - **新增 `app.yaml` 缓存命中逻辑** ([integrated_config.py](file:///d:/AI/xiaoyou-core/config/integrated_config.py))
    - 当 `app.yaml` 文件签名未变化，且引用的环境变量值未变化时，直接复用上次解析结果
  - **新增模型探测缓存命中逻辑** ([integrated_config.py](file:///d:/AI/xiaoyou-core/config/integrated_config.py))
    - 监控 `models`、`models/llm`、`models/qwen`、`models/voice/GPT`、`models/voice/SoVITS`、`models/whisper` 等关键目录签名
    - 目录和环境变量都未变化时，直接复用上次探测出的模型路径
  - **统一项目根路径解析** ([integrated_config.py](file:///d:/AI/xiaoyou-core/config/integrated_config.py))
    - `app.yaml` 与 `model_dir` 都改为基于项目根目录解析，避免依赖当前工作目录
  - **新增验证脚本** ([verify_startup_config_model_cache.py](file:///d:/AI/xiaoyou-core/tests/diagnostics/verify_startup_config_model_cache.py))
    - 校验缓存命中
    - 校验环境变量变化后 YAML 缓存失效
    - 校验模型目录变化后探测缓存失效并重建
- 关键改进：
  - 重启服务时，配置加载与模型探测不再每次全量重做
  - 环境变量变化、模型目录变化后仍能自动失效并回源重建
  - `model_dir` 现在遵循配置值解析，配置语义更一致
