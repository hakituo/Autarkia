## 2026-04-10（Active Care 睡眠模式误触发修复：引用/纠正语境守卫）

### 问题背景
- 用户消息"你自己本地记录的也是22.03睡觉，都跟你说了你那个是自己编的，我真的是，哎"被误判为晚安意图，触发了睡眠模式。
- 根因：规则层关键词"睡觉"过于宽泛，"22.03睡觉"是时间引用而非睡觉声明；语篇分析未识别纠正/记录引用语境。

### 本次改动
- `core/services/active_care/mode_state.py`
  - 新增 `_is_time_reference_sleep()`：检测"数字+睡觉"、"记录的+睡觉"、"睡觉+时间"等时间引用模式。
  - 新增 `_is_correction_context()`：检测"自己编的"、"搞错了"、"你瞎编的"等纠正/否认语境。
  - BERT路径增加守卫：SLEEP_NOW 若命中时间引用或纠正语境则跳过。
  - 规则路径增加守卫：先检查时间引用/纠正语境，再匹配关键词。
  - 关键词"睡觉"从第一组移除（太宽泛），改用"去睡觉"、"准备睡觉"、"要睡觉"等更精确模式。
- `memory/core/discourse.py`
  - `_CORRECTION_PATTERNS` 新增：自己编的、编的、搞错、弄错、写错、你+动词等模式。
  - 新增 `_RECORD_REFERENCE_PATTERNS`：记录的、写的、存的、显示的、本地记录等引用模式。
  - `analyze_discourse()` 新增 `is_record_reference` 检测，CORRECTION/RECORD_REFERENCE 均设 `trigger_blocked=True`。
  - 修复"去睡了"被误判为指令的问题：`^(去|快去)\s*(睡|休息|躺)` 不再视为指令。

### 验证结果
- `tests/verify_sleep_false_trigger_fix.py` 全部通过（28项测试）

## 2026-04-10（Active Care 架构重构：Prompt瘦身 + Executor拆分）

### 问题背景
- Active Care 的 prompt 注入了 23 个 section，最坏情况下达到 ~17000 字符（约 4000-5000 tokens），对于只需生成 1-2 句话的任务开销极大
- Executor 是 2004 行的 God Class，承担了 8+ 种不同职责，难以维护
- 状态键、晚安关键词等散布在多个文件中，存在大量重复代码
- 每次触发后 executor 追加 3 个 section 到 prompt_builder 之外，破坏了封装

### 本次改动
- **新增 `constants.py`**: 统一管理状态键（StateKeys）、晚安/早安关键词、话题关键词等常量
- **重写 `prompt_builder.py`**:
  - 删除空占位 section（emo_rule、task_block）
  - 合并 mode_status_text + sleep_context_text 为 combined_status_text
  - 合并 time_anchor + temporal_anchor_block 为统一的 temporal_anchor
  - 将 executor 追加的 3 个 section（话题多样性约束、时序交互线索、去重硬约束）移入 prompt_builder
  - tone_reference_text 上限从 7000 降至 3000 字符
  - voice_guide 仅在支持语音的客户端时注入
  - 新增 PromptSection 数据类和 format_breakdown() 方法便于调试
- **新增 `persona_resolver.py`**: 从 executor 提取人设解析逻辑（5个方法）
- **新增 `postprocessor.py`**: 从 executor 提取后处理管线
  - SleepSanitizer: 睡眠时间净化、睡眠场景邀请净化、低打扰输出强制、冗余睡眠问题净化
  - Deduplicator: 语义去重、重复锚点收集、非重复回退
  - LanguageHandler: 语言推断、英文重写、英文回退
  - LeakDetector: Prompt/推理泄露检测、安全消息提取
  - ActiveCarePostprocessor: 统一后处理编排器
- **新增 `state_persistence.py`**: 从 executor 提取状态持久化逻辑
- **重构 `executor.py`**: 从 2004 行瘦身至 871 行，仅保留核心编排逻辑
- **更新 `service.py`**: 导入 constants.StateKeys，替换关键硬编码字符串

### 优化效果
| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| Prompt section 数量 | 23（含3个executor外追加） | 19（全部在prompt_builder内） |
| Executor 行数 | 2004 | 871 |
| 模块数量 | 8 | 12（+constants, persona_resolver, postprocessor, state_persistence） |
| 空占位 section | 2（emo_rule, task_block） | 0 |
| 重复时间锚点注入 | 2次 | 1次 |
| 重复睡眠约束 | 3处 | prompt_builder 1处 + decision 1处 |

## 2026-04-10（Active Care 修复：睡眠不发消息 + voice_guide + tone_reference + 日志分离）

### 修复内容
- **睡眠模式不发消息 bug**：`_resolve_sleep_probe_policy` 使用 20% 随机概率 + 30-90分钟随机等待，导致睡眠期间几乎不发消息。修复为：晚安后3-10分钟随机发一条探测消息测试用户是否真睡了，之后按 `goodnight_probe_gap_seconds`（默认2小时）间隔允许发送
- **晚安后调度延迟**：`service.py` 中晚安后 `next_decision_ts` 从固定5分钟改为3-10分钟随机延迟
- **voice_guide**：恢复为所有客户端固定注入（用户确认所有客户端都需要）
- **tone_reference**：Ling（Ling）全量注入参考对话（max_chars=7000），Aveline 不注入参考对话
- **postprocessor 正则修复**：`strip_reasoning_segments` 中 `</think >` 改为 `</think\s*>` 兼容带/不带空格的格式
- **日志分离**：Active Care 日志分为两类独立文件
  - `active_care_schedule.log`：心跳/调度/运行时日志
  - `active_care_messages.log`：消息发送/决策/去重/跳过原因日志
  - 新增 `get_module_logger(name, module_file)` 函数支持模块级独立日志文件

### 平时不发消息的可能原因
- ~~`active_care_require_active_client` 默认值为 True~~ → 保持 True（没有客户端连接发了也收不到）
- ~~用户交互后 `base_delay=1200s`（20分钟）~~ → **已修复**：降为 `max(quiet_seconds, 300)` = 5分钟
- ~~LLM Bandit 决策倾向 `do_nothing`~~ → **已修复**：增加 no-send timeout 强制触发（距离上次发送超过 min_gap*4 且用户沉默超过 min_gap 时强制发送）
- LLM 决策返回 `should_send=False` → **已修复**：同上，no-send timeout 也覆盖此场景
- **晚安模式永不退出** → **已修复**：增加自动起床机制，晚安后超过8小时无交互自动退出 reduced_mode
