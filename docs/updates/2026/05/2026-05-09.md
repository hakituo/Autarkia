## 2026-05-09
- **🐛 修复 Active Care probable_sleep_probe_gap 阻塞10482s导致主动消息无法发送**：
  - 根因：`_resolve_probable_sleep_probe_policy` 中 `probe_gap = max(10800, 7200) = 10800`，导致 probable_sleep 模式下探针间隔长达3小时
  - 修复1：`PROBABLE_SLEEP_PROBE_GAP_SECONDS` 从 7200 降到 1800（30分钟）
  - 修复2：`max()` 改为 `min()`，让 PROBABLE_SLEEP_PROBE_GAP_SECONDS 优先
  - 修复3：添加 `max_wait_seconds = 3600` 上限保护，最多等1小时
  - 涉及文件：`core/services/active_care/constants.py`、`core/services/active_care/sleep_policy.py`
- **🐛 修复 Active Care perform_check 持续超时导致主动消息无法发送**：
  - 根因：决策流程中有 3 个串行 LLM 调用（`analyze_daily_push_priority` 20s + `decide_proactive_content` 25s + `trigger_message`→`llm.chat` 55s），最坏合计 100s，远超外层 90s 超时
  - 每轮 `perform_check` 都在 90 秒时被 `CancelledError` 中断，形成超时死循环
  - 修复1：外层超时从 90s 增加到 150s（覆盖最坏情况）
  - 修复2：`decide_proactive_content` 超时从 25s 降到 20s
  - 修复3：`llm.chat` 主模型超时从 55s 降到 45s，fallback 从 45s 降到 35s
  - 修复4：在决策流程各阶段添加计时日志，方便定位瓶颈
  - 涉及文件：`core/services/active_care/service.py`、`core/services/active_care/proactive_checker.py`、`core/services/active_care/executor.py`
- **🐛 修复 QQ 消息断句在前引号处错误分割，导致前引号单独成一条消息**：
  - 根因：LLM 输出中前引号 `"` 后跟换行符时，`_split_message_for_qq` 的 `split('\n')` 逻辑将前引号拆成独立一行，变成一条只有引号的消息
  - 现有的括号换行合并逻辑只处理了 `（`/`(` 的情况，没有覆盖中文引号 `\u201c`/`\u2018`/`「`/`『`
  - 修复：在换行拆分之前，用正则将前引号后的换行符合并（`([\u201c\u2018「『])\s*\n` → `\1`），同时合并闭合引号前的换行符（`\n\s*([\u201d\u2019」』])` → `\1`）
  - 涉及文件：`clients/bots/qq_adapter_utils.py`、`tests/unit/test_qq_split.py`
- **🐛 修复 DeepSeek 思考模式 reasoning_content 未回传 API 导致 400 错误**：
  - 根因：DeepSeek 思考模式要求多轮对话中 assistant 消息必须携带 `reasoning_content` 字段回传 API，但该字段在历史恢复链路中被3层丢失
  - 丢失点1：`save_conversation_history()` 将 thought_text 保存为独立的 system 消息（category="thinking"），而非 assistant 消息的 reasoning_content 字段
  - 丢失点2：`WeightedMemoryManager.get_history()` 只返回 `{role, content, timestamp}`，丢弃 reasoning_content、tool_calls、tool_call_id
  - 丢失点3：`fetch_history_for_scope()` 中 category="thinking" 被 exclude_categories 排除
  - 修复1：`history.py` 将 reasoning_content 保存到 assistant 消息的 metadata 中
  - 修复2：`weighted_memory_manager.py` get_history() 从 metadata 提取 reasoning_content、tool_calls、tool_call_id 并返回
  - 修复3：`context_budget.py` _sanitize_history_messages() 不再跳过含 reasoning_content 或 tool_calls 的空 content 消息，tool_calls 消息 content 设为 None
  - 修复4：`client.py` _parse_non_stream_response() 和 chat() 返回 reasoning_content 字段
  - 涉及文件：`core/agents/chat_agent_components/history.py`、`memory/weighted_memory_manager.py`、`core/agents/chat_agent_components/context_budget.py`、`core/llm/openai_compat/client.py`
