## 2026-05-17
- **⚡ 启动速度优化（35s → 8.3s → 预计 ~5s）**：
  - **AvelineService 懒初始化**：`__init__` 改为轻量构造（仅初始化属性默认值），重操作（`get_default_chat_agent()`、`get_weighted_memory_manager()`、`_load_character_config()`）延迟到 `initialize()` 中用 `asyncio.to_thread` 异步执行，避免阻塞事件循环
  - **WeightedMemoryManager 后台数据加载**：`load_memory()`、`_load_weighted_data()`、`_migrate_legacy_data()`、`clean_memory_records()` 等磁盘I/O操作移到后台线程执行，不再阻塞主线程
  - **替换 import torch 为轻量级GPU检测**：`check_memory_pressure()` 中先用 `nvidia-smi` 子进程检测GPU（<0.1s），失败再回退到 `import torch`（~1.5s），避免首次导入 PyTorch 的开销
  - **VectorSearch 数据导入延迟化**：`ChatAgent.initialize()` 中的 AI Studio 文档清理和对话示例数据导入移到后台线程，不再阻塞启动
  - **模块预加载并行化**：`lifecycle_manager` 中同优先级的模块预加载从串行改为 `run_in_executor` 并行执行
  - **CloudRouterLLMModule 并行初始化/关闭**：`initialize()` 和 `shutdown()` 中云端客户端的串行遍历改为 `asyncio.gather()` 并行执行
  - **CloudRouterLLMModule 延迟创建非默认客户端**：启动时只创建默认 provider 的客户端，其他云端客户端在首次使用时延迟创建，减少 `get_llm_module()` 耗时
  - **cpp_scheduler_engine 懒加载**：全局实例从模块级创建改为 `__getattr__` 懒加载，避免 `import` 时触发 C++ 扩展加载（~2s）；`lifecycle_manager` 中构造移到 `asyncio.to_thread` 避免阻塞事件循环
  - **get_llm_module() 移到 to_thread**：`ChatAgent.initialize()` 中 `get_llm_module()` 工厂函数移到线程池执行，避免阻塞事件循环
  - **细粒度计时**：`ChatAgent.initialize()`、`cpp_scheduler_engine.start()` 加细粒度计时，便于定位剩余瓶颈
- **🐛 修复 Qwen3-TTS torch.compile 失败**：
  - 问题：`torch.compile` 报错 `A callable function is expected, but <class 'qwen_tts.inference.qwen3_tts_model.Qwen3TTSModel'> is provided`
  - 根因：`Qwen3TTSModel` 是一个包装类（wrapper），继承自 `object`，不是 `nn.Module`，也不可调用。`torch.compile` 需要可调用对象
  - 修复：将 `torch.compile(self._model, ...)` 改为 `torch.compile(self._model.model, ...)`，编译内部的 `Qwen3TTSForConditionalGeneration`（真正的 `nn.Module`）
  - 影响范围：`initialize()` 和 `move_to_gpu()` 两处编译逻辑
- **🐛 修复 Active Care Storage 写入文件失败 WinError 2**：
  - 问题：`_write_json_file_unlocked` 中 `os.replace(tmp, filepath)` 因 `.tmp` 文件不存在而失败，3次重试均无法恢复
  - 根因1：`aiofiles.open` 写入后没有显式 `flush()` + `os.fsync()`，Windows 上文件可能还在 OS 缓冲区
  - 根因2：Windows 杀毒软件可能临时锁定/删除新创建的 `.tmp` 文件
  - 根因3：重试逻辑缺陷——失败后只重试 `os.replace`，不重新创建 `.tmp` 文件
  - 修复：将 `.tmp` 写入移入重试循环内，每次重试都重新写入；添加 `flush()` + `fsync()` 确保落盘；`os.replace` 前检查文件存在性；最终失败后清理残留 `.tmp` 文件
