## 2026-05-12
- **🐛 修复 Active Care conversation_incomplete 绕过交互保护导致退避惩罚完全失效**：
  - 根因：`_execute_send_or_skip` 中 `conversation_incomplete` 允许绕过 `recent_user_interaction_guard`，即使 `non_response_count >= 2` 也会在过了安静期后绕过，导致退避惩罚完全失效
  - 修复：`non_response_count >= 2` 时，不再绕过交互保护（无论是否 conversation_incomplete）
  - 涉及文件：`core/services/active_care/proactive_checker.py`
- **🐛 修复 Active Care 连续无响应时退避惩罚太弱**：
  - 根因：退避基数 1.4 太小（5次不回复仅 5.38 倍），CAP 6.0 太低，没有连续无响应上限
  - 修复1：退避基数从 1.4 增加到 1.8（3次不回复就 5.8 倍，5次就 18.9 倍）
  - 修复2：CAP 从 6.0 增加到 12.0（最多放大 12 倍，即 2 小时间隔）
  - 修复3：新增 `MAX_CONSECUTIVE_NON_RESPONSES_BEFORE_SKIP=4`，超过 4 次不回复直接跳过，1小时后再检查
  - 涉及文件：`core/services/active_care/constants.py`、`core/services/active_care/proactive_checker.py`
- **🐛 修复 Active Care 优先级分析缓存未随睡眠状态失效**：
  - 根因：`analyze_daily_push_priority` 的缓存只检查时间间隔，不检查 `reduced_mode_active` 是否变化。用户起床后，缓存仍返回包含"叫起床"的旧优先级
  - 修复1：保存分析结果时同时保存 `daily_push_priority_reduced_mode`
  - 修复2：读取缓存时比较 `reduced_mode_active`，不一致则缓存失效
  - 涉及文件：`core/services/active_care/priority_analyzer.py`、`core/services/active_care/proactive_checker.py`
- **🐛 修复 Active Care 用户已起床但仍发送"还没起来"消息**：
  - 根因：`_exit_goodnight_mode` 执行顺序错误——先 sync Daily Record（可能卡住），再 save_state（清除晚安模式）。如果 sync 卡住，state 永远不更新，系统一直认为用户在睡觉
  - 修复：调整执行顺序——先 `save_proactive_state(goodnight_clear)`（清除晚安模式），再 `_sync_goodnight_sleep_to_daily_record`
  - 涉及文件：`core/services/active_care/proactive_checker.py`
- **🐛 修复 Active Care wakeup 时间不断更新 + 150s 超时仍发生**：
  - 根因1：`_try_exit_goodnight_on_awake_signals` 没有检查 `last_goodmorning_ts`，即使已经退出过晚安模式也会重复触发 `_exit_goodnight_mode`
  - 根因2：`SleepStateManager.sync_sleep_time/sync_wakeup_time` 没有超时保护，可能卡死
  - 修复1：添加 `last_goodmorning_ts` 检查，如果已经退出过就跳过
  - 修复2：给 `SleepStateManager` 的 sync 方法添加 `asyncio.wait_for` 5s 超时保护
  - 修复3：给 `_exit_goodnight_mode` 和 `_sync_goodnight_sleep_to_daily_record` 内部添加计时日志
  - 涉及文件：`core/services/active_care/proactive_checker.py`
