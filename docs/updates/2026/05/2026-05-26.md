## 2026-05-26 修复 LLM 优先使用 web_search 而非 search_chat_history 的问题

### 问题
- 用户提到过去的对话（如"我之前不是跟你说过那个钟老师吗"）时，LLM 使用 `web_search` 搜索互联网而非 `search_chat_history` 搜索聊天记录
- 导致搜到错误的人（建筑城规学院的钟刊 vs 大数据与软件学院的钟刊）
- 即使后来用户明确说"搜历史记录"，LLM 仍然没有正确使用 `search_chat_history`
- 根因分析发现：即使用户5月1日确实聊过"重庆大学副教授"，但5月26日用"钟老师/钟刊"搜索时搜不到，因为关键词不匹配

### 修复（四层约束）
1. **search_chat_history_tool.py** — 改进工具描述，明确"当用户提到过去对话时必须优先使用此工具，而不是web_search"
2. **context_persona.py** — 扩展关键词触发列表，新增"我之前"、"跟你说过"、"之前不是"、"搜历史"等
3. **context_gathering.py + assembler.py** — 实现 `get_tool_injection()`，当 `search_chat_history` 被激活时在 prompt 中注入工具使用优先级引导
4. **search_chat_history_tool.py** — 新增记忆摘要回退搜索：当聊天记录搜不到时，自动回退到 `search_memory` 搜索记忆摘要，解决"用户用新名字提到旧话题"的问题

## 2026-05-26 修复 QQ bot /模型 命令返回 401 导致模型列表为空

### 问题
- QQ 中使用 `/模型` 命令时，MODEL REGISTRY 显示空白（无模型数据）
- 服务端日志显示所有 `/api/models` 相关请求均返回 `401`：
  - `GET /api/models?type=llm HTTP/1.1" 401`
  - `GET /api/v1/image/models HTTP/1.1" 401`
  - `GET /api/models HTTP/1.1" 401`

### 根因
- [main.py:security_middleware](main.py#L192) 拦截所有 `/api/` 路径，要求 `web_access_token`
- **只有 WebSocket 升级请求被豁免 token 校验**（第 201 行），但 QQ bot 客户端发起的是**普通 HTTP GET 请求**
- QQ bot 从本地 `127.0.0.1` 连接，未携带任何认证头 → 被 401 拦截 → 返回空数据

### 修复
- **[main.py:204-207](main.py#L204-L207)** — 在 `security_middleware` 中增加本地连接豁免：对 `127.0.0.1`/`::1`/`localhost` 的请求跳过 `web_access_token` 校验
- 与 WebSocket 豁免逻辑保持一致，注释已说明"内部适配器（如 QQ）通过本地连接"

### 验证脚本
- [tests/diagnostics/verify_local_api_auth_bypass.py](tests/diagnostics/verify_local_api_auth_bypass.py) — 验证本地 API 请求不再返回 401
