## 2026-05-24 移除 LLM 输出长度限制

### 问题
- LLM 回复被 max_tokens 限制截断，例如 845 字的回复在中间被截断
- 整个调用链上存在多层 max_tokens 硬编码默认值和回退值

### 修复
全面移除聊天对话路径上的所有 max_tokens 限制，改为 None（不限制），由模型自行决定输出长度：
- `infer_max_tokens()` 改为返回 None
- `handler.py` 移除 max_tokens 硬编码（256/512/600/400），改为 None
- `streaming.py` 移除 `max_tokens or 512` 回退
- `message_utils.py` 移除 `min(max_tokens, 8192)` 硬上限
- `AvelineService` 三个方法（stream_conversation/stream_generate_response/generate_response/handle_conversation）默认值从 512 改为 None
- `stream_orchestrator.py` 默认值从 512 改为 None
- `chat.py` 路由 `_resolve_max_tokens()` 回退从 512 改为 None
- `websocket streaming.py` 回退从 8192 改为 None
- `text_model_adapter.py` 三个方法默认值从 512 改为 None
- `model_adapter.py` 移除 512 回退
- `trm_adapter.py` 移除 8192 回退
- `stream_generator.py` / `sync_generator.py` 回退值改为 None
- `aveline_client.py` default_max_tokens 从 2048 改为 None
- `infer_service_client.py` 默认值从 512 改为 None
- `text_adapter_request_utils.py` normalize_max_tokens 默认值从 1024 改为 None
- `app.yaml` model.generation.max_new_tokens 从 1024 改为 0
