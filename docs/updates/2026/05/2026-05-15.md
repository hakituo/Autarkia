## 2026-05-15
- **🐛 修复 Active Care 固定1小时间隔问题**：
  - 问题：Active Care 每次都以固定1小时间隔发送消息，没有随机性
  - 根因1：`_build_output_format_schema` 中的示例直接给了 `next_check_seconds: 3600`，LLM 照抄返回固定值
  - 根因2：`_build_output_format_schema` 没有给 LLM 任何关于 `next_check_seconds` 的范围指导
  - 根因3：抖动比例太小（发送成功 0.18，不发送 0.25），导致实际间隔几乎固定
  - 修复1：`decision.py` 在输出格式说明中加入 `next_check_seconds` 范围指导（刚互动600~1200，正常1200~2400，低打扰2400~4800，深夜3600~7200），并明确要求"必须随机取值，避免固定间隔"
  - 修复2：`decision.py` 将示例从单一 `next_check_seconds: 3600` 改为两个不同场景的示例（900和2700）
  - 修复3：`proactive_checker.py` 将发送成功抖动比例从 0.18 增大到 0.35，不发送抖动比例从 0.25 增大到 0.40
- **🐛 修复 decision.py LLM 响应解析导致 should_send 被错误设为 False**：
  - 问题：LLM 返回了有效的 JSON（`should_send: true`），但 decision.py 将其解析为空响应，导致重试后得到空结果，最终 `should_send=False`
  - 根因：`decide_proactive_content` 中 LLM 响应解析逻辑（L772-776）只处理 `status == "success"` 和 `error` 两种情况。当 LLM 返回 `{'response': '```json\n...'}` 格式（无 `status` 字段）时，走 `else` 分支 `raw.get("error")` 得到空字符串
  - 修复：增加 `elif raw.get("response") or raw.get("text")` 分支，当 dict 有 `response` 或 `text` 字段但无 `status` 字段时正确提取内容
  - 同时修复了重试响应（retry_raw）的相同解析问题
