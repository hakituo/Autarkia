## 2026-05-25 修复内部适配器 WebSocket 连接 403 问题

### 问题
- QQ adapter 等内部适配器通过 WebSocket 连接 `/api/v1/ws` 时被 403 拒绝
- 原因：`security_middleware`（HTTP 层）拦截了 WebSocket 升级请求，要求 `web_access_token`；`adapter.py`（WebSocket 层）也要求 `web_access_token`，但内部适配器不应走 Web 端的 token 校验

### 修复
1. **security_middleware 跳过 WebSocket 升级请求** — 检测 `Upgrade: websocket` 头，直接放行，由 WebSocket 层自行处理认证
2. **adapter.py 区分本地/远程连接** — 来自 127.0.0.1/::1/localhost 的连接视为内部适配器，跳过 `web_access_token` 校验；远程 Web 客户端仍需提供 token

## 2026-05-25 修复 [TOOL_CALL] 格式泄露给用户（全链路）

### 问题
- MiniMax-M2.5 等模型有时输出 `[TOOL_CALL]{tool => "精灵文字回复", args => {--text "实际消息"}}[/TOOL_CALL]` 格式
- 这是模型训练数据中自带的工具调用格式，项目未注册这些工具，导致原始格式被直接发送给用户
- Active Care 和正常聊天流程均受影响

### 修复
1. **postprocessor._strip_tool_call_segments** — Active Care 后处理中剥离 `[TOOL_CALL]...[/TOOL_CALL]`，提取 `--text` 参数的实际文本
2. **LeakDetector** — 将 `[TOOL_CALL]`、`[/TOOL_CALL]` 加入 `strong_leak_markers`
3. **openai_compat/client.py** — 非流式解析中增加 `[TOOL_CALL]` 格式处理，在 DSML 解析之后
4. **streaming.py** — 流式聊天后处理中增加 `[TOOL_CALL]` 格式清理
5. **handler.py** — 非流式聊天后处理中增加 `[TOOL_CALL]` 格式清理
