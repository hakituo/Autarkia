## 2026-05-27 修复双QQ角色共用同一人设 - profile_filename 全链路透传 + 全局状态隔离

### 问题
- 双QQ独立角色架构中，两个QQ Bot只能使用同一个人设，无法各自使用不同人设
- Aveline和Ling虽然在 `dual_qq_config.json` 中配置了不同的 `profile_filename`，但后端始终使用全局 PersonaManager 的当前人设
- 在Ling账号切换人设后，Aveline账号也被影响

### 根因
1. `profile_filename` 参数在后端调用链中被完全丢弃（handlers → streaming → service → prompt 全未透传）
2. `_sync_config_from_backend` 启动时从后端全局API获取人设，覆盖了adapter自身配置
3. `handle_switch_persona` 切换人设时调用全局 `PersonaManager.set_persona()`，影响所有adapter实例
4. `handle_switch_persona` 调用后端全局API `/api/personas/switch`，影响全局状态

### 修改文件
**全链路透传 profile_filename（8个文件）：**
- `clients/bots/qq_adapter_session.py` - send_text 人设优先级：session prefs > adapter配置 > 全局
- `core/interfaces/websocket/adapters/handlers.py` - 提取 profile_filename 并传给 streaming handler
- `core/interfaces/websocket/adapters/streaming.py` - handle_stream 透传 profile_filename
- `core/services/aveline/service.py` - stream_conversation/stream_generate_response 透传
- `core/services/aveline/stream_orchestrator.py` - stream_conversation_events 透传
- `core/agents/chat_agent_components/persona_system/prompt/data.py` - get_prompt_data 支持外部 profile_filename
- `core/agents/chat_agent_components/persona_system/prompt/assembler.py` - build_persona_prompt_split/build_complete_message_list 透传
- `core/agents/chat_agent_components/context.py` - build_conversation_history 传给 build_complete_message_list

**全局状态隔离（3个文件）：**
- `clients/bots/qq_adapter_main.py` - _sync_config_from_backend 优先使用adapter自身配置的profile_filename
- `clients/bots/handlers/resources.py` - handle_switch_persona 双QQ模式下不调全局API、不改变全局PersonaManager
- `clients/bots/qq_adapter_session.py` - send_text 人设优先级调整

### 附带修复
- NapCat WebUI 前端未构建导致访问返回 `{"code":-1}`，已构建前端并复制到 static 目录
- Ling NapCat OneBot11 配置缺少 WebSocket 服务器（3002端口），已添加

### 并发
- 两个角色同时聊天不会堵塞，各自有独立的WS连接和流式响应
