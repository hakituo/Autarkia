- **ScreenCaptureTool 增加按分辨率自适应压缩策略（替代统一 PNG）**
  - **背景**: 用户指出 2.5K 屏压到 1920 可以，但 4K 屏压到 1920 会丢细节。实测验证：1280 宽开始文字识别出错（xiaoyao-core/Loo File），1024 宽严重幻觉。查询 Qwen3-VL 官方：视觉编码器固定 448x448 patch，2048px 以上触发自动缩放防 OOM。需要按原图分辨率分档选择压缩目标宽度。
  - **修复**:
    - 新增 _get_compress_target_width(src_width) 按原图宽度分档：≤1920 不缩，1921-2560 缩到 1920（75%），2561-3840 缩到 2560（67%），>3840 缩到 3000（兜底）
    - 新增 _compress_screenshot(image) 方法：按目标宽度 LANCZOS 缩放 + JPEG q=85 编码，RGBA 自动转 RGB
    - 修改 _capture_active_screen：截图后走自适应压缩，保存为 .jpg（原为 .png），日志输出原始尺寸→目标宽度→缩放比→JPEG 体积
    - 修复 _compress_screenshot 内部 Image.LANCZOS 未 import Image 的 NameError
    - 原则：缩放比不低于 67%，避免 4K 粗暴砍半丢失文字细节；4K 的 67% 比 1920 的 50% 多保留 78% 像素
  - **验证**:
    - `tests/scripts/tools/compare_screen_capture_compression.py 5 种压缩策略对比实测：1920 宽文字零损失，1280 开始出错，1024 严重幻觉`
    - `tests/scripts/tools/verify_screen_capture_tool.py 验证结果 10/10 通过：新增测试 6.5 覆盖 7 个分辨率分档（1366/1920/2560/3000/3840/5120/7680）+ 2.5K 纯色图压缩 + RGBA 自动转 RGB`
    - `实测 1707 宽屏幕：PNG 193KB → JPEG q85 145KB，省 25% 体积，文字识别无损失`
  - **备注**:
    - Qwen3-VL 视觉编码器固定 448x448 patch 处理，平台侧不做压缩，只有 256K 上下文限制
    - 4K 屏原图约 1MB+，base64 后约 300K tokens 会撑爆上下文，压缩到 2560 宽后约 300KB（70K tokens）安全
    - 5 档压缩对比图保存在 companion_data/temp/compression_test/ 供人工查看

  - **背景**: Telegram 适配器此前把 [MEME] 表情包当普通大图发送，没有像 QQ 那样用 subType=1 显示为小图，导致表情包在 Telegram 里显示过大
  - **根因**:
    - _send_media_tags 不区分表情包和普通图片，统一用 send_photo_path_to_chat 发原图
    - Telegram 没有 CQ 码那种 subType 小图标记，需要通过实际缩小图片尺寸来模拟小图效果
  - **修复**:
    - adapter.py 新增 _resize_image_bytes：用 Pillow 把图片等比缩小到 240×240 以内（只缩小不放大），RGBA/P 模式先合成白底转 RGB，输出 JPEG quality=85
    - adapter.py 新增 send_meme_path_to_chat：表情包专用发送，先缩小再 send_photo；缩小失败回退原图
    - _send_media_tags 改为区分处理：[MEME] 表情包走 send_meme_path_to_chat（小图），[IMG]/[BM] 走 send_photo_path_to_chat（大图），与 QQ 适配器对齐
    - send_list 用 (path, is_meme) 元组列表，按类型分发到对应的发送方法
  - **验证**:
    - `venv_cpu\Scripts\python.exe -c "import ast; ast.parse(...); from PIL import Image; print(f'Pillow {Image.__version__} 可用')"`
  - **备注**:
    - Telegram 没有 QQ 那种 CQ:image subType=1 的内建小图标记，只能通过实际缩小图片尺寸模拟小图视觉效果
    - Pillow 12.2.0 已在 venv_cpu 中可用，无需额外安装
    - 缩小尺寸设为 240×240（表情包尺寸），与 QQ 小图视觉大小接近

## 2026-08-06（星期四）

- **Telegram 适配器改为 config/telegram_config.json 的 enabled 开关控制启停（默认关闭）**
  - **背景**: 此前 Telegram 适配器靠有无 TELEGRAM_BOT_TOKEN 判断是否启动，没有显式开关，且配置散落在 .env，不便统一管理
  - **根因**:
    - lifespan.py 用 os.getenv('TELEGRAM_BOT_TOKEN') 判断启动，缺少显式 enabled 开关
    - config/telegram_config.json 没有 enabled 字段
  - **修复**:
    - config/telegram_config.json 新增 enabled 字段，默认 false
    - config/settings_adapters.py 的 TelegramAdapterSettings 新增 enabled 字段（默认 False）
    - get_telegram_adapter_settings() 读取 JSON 的 enabled，并支持 TELEGRAM_ENABLED 环境变量覆盖
    - clients/bots/telegram/settings.py 导出 ENABLED 变量
    - core/lifecycle/lifespan.py 改用 ENABLED + TELEGRAM_BOT_TOKEN 双重判断：enabled=true 且有 token 才启动；enabled=true 但无 token 警告；enabled=false 跳过并记录日志
  - **验证**:
    - `venv_cpu\Scripts\python.exe tmp_verify_tg_enabled.py 输出：ENABLED=False, BOT_TOKEN=8693...(存在)，→ Telegram 适配器未启用`
  - **备注**:
    - 配置统一收敛到 config/telegram_config.json（符合项目规则：config 内容统一在 config 文件夹管理）
    - 默认 enabled=false，需要用 Telegram 时把 enabled 改成 true 即可
    - 仍支持 TELEGRAM_ENABLED 环境变量覆盖（环境变量优先级最高）
