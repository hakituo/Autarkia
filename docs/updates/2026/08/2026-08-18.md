## 2026-08-18（星期二）

- **修复流式请求（mode=stream）Prompt Cache 命中率记录缺失问题**
  - **背景**: 日常聊天使用云端 DeepSeek v4 模型走流式请求，但 logs/prompt_cache_stats.log 只有 mode=sync 的记录，流式请求的 prompt_cache_hit_tokens / prompt_cache_miss_tokens 从未被记录，导致无法评估真实场景下的缓存命中率表现。
  - **根因**:
    - stream_parser._extract_sse_content 的 usage 提取条件错误：`if not choices and isinstance(usage, dict) and usage:`，但真实 DeepSeek API 的 usage chunk 与 choices（finish_reason=stop 的空 delta 块）在同一个 SSE 数据中同时存在，导致条件完全无法命中，usage 被当做 finish chunk 丢弃。
    - 附带问题：SSE 首包仅设置 delta.role=assistant 但无内容，被误判为解析失败放入 pending_json，后续 chunk 到达时触发 Discarding corrupted pending_json 噪音告警。
  - **修复**:
    - 重写 stream_parser._extract_sse_content：usage 提取不再依赖 choices 是否为空，改为无论 choices 是否存在都优先检查并提取 usage；一个 SSE chunk 可能同时 yield 多条结果（如 usage + finish），因此返回值改为 (parsed_items 列表, new_reasoning_mode)。
    - parse_sse_stream 同步适配：遍历 parsed_items 逐个 yield；只要 JSON 成功解析就不再放入 pending_json，避免首包 role-only 块的误丢弃告警。
    - 返回值类型收紧：_extract_sse_content 永远返回 tuple 不返回 None，异常时返回 ([], reasoning_mode)。
  - **验证**:
    - `tests/scripts/prompt_cache/_debug_real_deepseek_stream.py 用真实 DeepSeek API 调用，最后一条日志出现 mode=stream。`
    - `prompt_cache_stats.log 新增 [D] mode=stream hit=0 miss=100 model=deepseek-v4-flash 记录。`
    - `复跑调试脚本时不再出现 Discarding corrupted pending_json 警告。`
  - **备注**:
    - DeepSeek 返回格式：SSE 最后一个 chunk 同时包含 choices[0].finish_reason=stop 与 usage.prompt_cache_hit_tokens/miss_tokens，两者共存而非独立 chunk。
    - deepseek_client._build_payload 已对 stream=True 注入 stream_options: {include_usage: true}，该部分无需修改。
