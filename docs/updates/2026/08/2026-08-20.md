- **🔴 修复流式对话历史落库静默丢失（08-18 真流式改造回归）**
  - **背景**: 08-18 真流式改造把 _save_conversation_history 的 create_task 调度从 yield done 之前移到之后，导致正常对话完全不写入短期记忆；主动消息走 append_proactive_message 直接写库不受影响。
  - **根因**:
    - streaming.py 的保存调度放在 `yield {"done": True}` 之后，但消费端收到 done 后 break（stream_orchestrator.py:190、WS 适配器收到 response_done 后 break），async 生成器引用被丢弃，asyncio 的 asyncgen finalizer 调度 aclose()，GeneratorExit 抛在 yield done 处，yield 之后的保存代码永远不执行
    - 注释声明『必须在 yield done 之前调度』，代码却相反，自相矛盾（4/28 曾修复同一问题，08-18 重新引入）
  - **修复**:
    - 保存调度移入 yield done 的 try/finally：正常消费与 break/aclose 两条路径都会执行 finally，保证保存任务一定被调度；create_task 异步执行不影响 done 信号送达

    - 人设缺少'情报应通过 peer chat 互通、不得直接向用户打听另一角色私事'的明确约束。
  - **修复**:
    - core_aveline.json：新增场景与 active_care_guidelines，用户倾诉需让Ling知情时，主动用 message_peer 发起 peer chat 把情报告知Ling；
    - core_ling.json：新增场景与 active_care_guidelines，主人与Aveline的私事只经 peer chat 得知，绝不向主人盘问'你怎么了'，也不用 search_chat_history 的 peer_role 窥探私聊；
    - message_peer_tool.py / search_chat_history_tool.py：工具说明澄清 peer chat 是互通情报的正确渠道，peer_role 搜索的是角色间互聊记录而非用户与另一角色私聊。
