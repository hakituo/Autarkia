## 2026-08-02（周日）

- **peer_chat 睡眠门禁由用户改为角色：用户睡觉时正常触发，角色睡觉时不触发**
  - **背景**: peer_chat 是角色之间的互聊（剧本发给对方角色 QQ，不发消息给用户），原逻辑却用用户睡眠门禁拦截，导致用户睡觉时 peer_chat 完全不触发；同时部分路径缺少角色睡眠门禁，可能在角色睡觉时触发互聊。
  - **根因**:
    - peer_chat 是角色之间的互聊（剧本发给对方角色 QQ），不会给用户发消息，因此用户睡觉时不会被打扰
    - 原逻辑在 peer_chat_scheduler.py 与 character_daily/engine.py 三处设置了用户睡眠门禁，导致用户睡觉时 peer_chat 完全不触发，浪费了用户睡眠期间的互聊时段
    - _check_and_trigger_for_role 与 _try_proactive_assignment_negotiation 缺少角色睡眠门禁，可能在角色睡觉时触发互聊
  - **修复**:
    - peer_chat_scheduler.py: _try_negotiation_peer_chat 移除用户睡眠门禁，保留并复用新辅助方法 _is_either_character_sleeping 做角色睡眠门禁
    - peer_chat_scheduler.py: _check_and_trigger_for_role 将用户睡眠门禁替换为角色睡眠门禁（任一角色 SLEEPING 即跳过）
    - peer_chat_scheduler.py: _try_proactive_assignment_negotiation 新增角色睡眠门禁（与提醒分工协商一致）
    - peer_chat_scheduler.py: 新增 _is_either_character_sleeping 辅助方法，统一角色睡眠判断逻辑（只拦 SleepPhase.SLEEPING，不拦 NIGHT_AWAKE）
    - character_daily/engine.py: _maybe_trigger_peer_chat 移除 is_user_sleeping 调用，改为基于 plan.current_activity == SLEEPING 的角色睡眠门禁，诊断日志字段 user_sleeping 改为 char_sleeping

    - `现有测试 verify_sleep_limit_and_ling_schedule.py / verify_probable_sleep_removed.py 不受影响（它们检查的是 good_morning_proactive 与 nudge，与 peer_chat 无关）`
  - **备注**:
    - is_user_sleeping 方法保留：good_morning_proactive.py 仍在使用
