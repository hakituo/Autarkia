## 2026-08-23（周日）

- **修复 QQ 表情包发送白边问题：改用自定义贴纸(mface)通道并修正字段映射**
  - **背景**: QQ 表情包 PNG 通过普通图片通道(CQ:image)发送时被转 JPG，透明区域被填成白边；改为 add_custom_face 上传为自定义贴纸后以 mface 发送，但 fetch_custom_face_detail 返回字段是 md5/epId/resId，旧代码误读 emoji_id/emoji_package_id，导致始终取不到值回退 CQ:image。
  - **根因**:
    - fetch_custom_face_detail 的 emojiInfoList 字段为 md5/epId/resId，旧代码按 emoji_id/emoji_package_id 读取导致取空。
    - mface CQ 码缺少 key 字段（NapCat 发送 mface 需 emoji_id/emoji_package_id/key/summary）。
    - 表情缓存只按文件路径键控，多 QQ 账号共用会导致贴纸字段串号。
  - **修复**:
    - 按 NapCat 源码映射：md5→emoji_id、epId→emoji_package_id、resId→key、desc→summary。
    - mface CQ 码补充 key 字段，summary 做 CQ 安全净化（去逗号/方括号/&）。
    - 按本地文件 MD5 精确匹配刚上传的贴纸，避免取到旧贴纸。
    - 贴纸未同步时最多重试 3 次 fetch（间隔 1.5s）。
    - 表情缓存改为按账号(napcat_ws_url)+文件路径键控，账号间隔离。
    - 顺手清理 message.py 中无用的 sent_any 死代码。
  - **验证**:
    - `venv_core python -m ruff check clients/bots/qq/session/message.py 通过`
    - `venv_core python tests/scripts/qq/verify_meme_mface.py 全部通过（字段映射/重试/回退/账号隔离 4 组用例）`

## 2026-08-23（周六）

- **回退 QQ 表情包自定义表情（mface）发送方案，恢复直接 CQ:image 发送**
  - **背景**: 此前为了让透明 PNG 表情包保留透明背景，尝试走 NapCat add_custom_face + mface 收藏表情通道发送。实测中该通道在多账号下返回 -13100（QQ 内核拒绝），且经 NapCat 源码与官方文档确认：OneBot 层没有把收藏表情作为消息发送的通道，mface 引用的是商城表情资源体系，与收藏表情字段（md5/resId/epId）不对应。

  - **修复**:
    - message.py 回退到 mface 引入前的状态（50ccd3fc^）：删除 import hashlib、_meme_face_cache 缓存、_send_meme_as_custom_face、_send_mface

    - 还原 sent_any 死代码清理改动
    - 删除测试文件 tests/scripts/qq/verify_meme_mface.py 及临时 _face_dump.json
  - **验证**:
    - `venv_core\Scripts\python.exe tests\scripts\qq\verify_media_tags.py`
