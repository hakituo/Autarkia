## 2026-03-28（添加LLM API缓存机制）

- 问题描述：
  - 用户反馈缓存命中率很低，API请求次数虽然减少但token消耗却越来越高
  - 分析代码发现系统中根本没有针对LLM API调用的缓存机制
  - 每次相同或相似的输入都会发送新的API请求，导致token浪费
- 问题原因：
  - `OpenAIClient`（处理DeepSeek等云端API调用）没有缓存机制
  - `search_cache_manager`虽然已存在，但没有被用于LLM API调用
  - 缺少缓存键生成、缓存获取和设置的逻辑
- 修复内容：
  - **OpenAIClient** ([openai_client.py](file:///d:/AI/xiaoyou-core/core/llm/openai_client.py))
    - 新增 `use_cache` 参数，默认启用缓存
    - 新增 `_generate_cache_key()` 方法，基于messages和参数生成MD5缓存键
    - 新增 `_get_cache()` 和 `_set_cache()` 方法，使用search_cache_manager
    - 新增 `_cache_stats` 统计缓存命中、未命中和总请求数
    - 修改 `chat()` 方法，在API调用前检查缓存，命中后直接返回
    - 修改 `get_status()` 方法，添加缓存统计信息（包括命中率）
    - 缓存有效期设置为3600秒（1小时）
  - **验证脚本** ([test_llm_cache.py](file:///d:/AI/xiaoyou-core/tests/test_llm_cache.py))
    - 新增测试脚本验证缓存功能是否正常工作
    - 测试search_cache_manager的基本功能
    - 测试LLM客户端的缓存集成
- 预期效果：
  - 相同输入的重复请求会直接从缓存返回，无需调用API
  - 显著降低token消耗，节省成本
  - 提高响应速度，缓存命中时几乎即时返回
  - 可通过get_status()查看缓存统计和命中率
