## 2026-07-05（周日）

- **修复 /wake 立即唤醒后消息仍被静默累积的 bug**
  - **背景**: QQ 解耦重构后用户反馈：发送 /wake 命令虽然返回『已立即唤醒 aveline，当前状态：night_awake』，但紧随其后的消息仍被 ReplyPolicy 判定为 dnd_sleeping_silent(activity=sleeping, ac_sleeping=False) 静默累积，导致角色唤不醒。
  - **根因**:
    - SleepManager.notify_sleep_interruption() 只更新了 sleep_manager 内部状态（phase=NIGHT_AWAKE, is_sleeping=False），未触发 CharacterDailyEngine 重新计算 plan.current_activity
    - CharacterDailyEngine.get_current_activity() 直接返回缓存的 plan.current_activity，未重算
    - CharacterDailyEngine 主循环 tick 间隔为 2 分钟（±20% jitter），/wake 后的下一次 tick 之前 activity 仍是过时的 sleeping
    - ReplyPolicy.evaluate_reply_state() 综合判定 is_dnd = activity in DO_NOT_DISTURB_ACTIVITIES or ac_sleeping；即使 ac_sleeping=False，只要 activity=sleeping 仍判定为 DND 静默累积
  - **修复**:
    - 在 CharacterDailyEngine 新增公开方法 refresh_current_activity(role_id)，强制重新计算指定角色 plan.current_activity 并立即持久化
    - 在 routers/v1/life.py wake API 的两个分支（is_sleeping=True 主分支、is_sleeping=False 但 ac_cleared=True 残留晚安态清理分支）调用 _refresh_character_daily_activity(role_id) 同步刷新 character_daily activity
    - _refresh_character_daily_activity 容错处理 engine 未初始化或刷新失败场景，仅记录 warning 不影响 wake 主流程
  - **验证**:
    - `venv_core\Scripts\python.exe -m pytest tests/unit/test_life_sleep_wake_route.py -v`
    - `venv_core\Scripts\python.exe -m pytest tests/unit/test_reply_policy_support.py tests/character_daily/test_character_daily_plan_tool.py -v`
  - **备注**:
    - 此 bug 与 QQ 解耦无关，是 wake API 一直存在的状态同步缺口，只是用户在解耦后测试时复现
    - MessageDispatcher._resolve_session_id 私聊 is_at_me=True 丢失的 bug 仍在待修，但与本问题无关，后续单独处理

## 2026-07-05（周日）

- **新增：角色按作息时间进入睡眠时主动给用户发晚安消息**
  - **背景**: 用户反馈角色睡觉时没给用户发晚安之类的消息。希望角色在要睡的时候，通过 active care 系统主动给用户发一个『我要睡了，晚安』的消息。调查发现：当前完全没有『角色进入 SLEEPING 状态时主动发晚安消息』的机制，SleepManager 在按计划作息时间进入 SLEEPING 时没有任何 hook/事件通知 active_care。但有意思的是 is_assistant_goodnight 机制已经实现了『检测助手说晚安 → 自动进入睡眠会话』的闭环，只是没人补上『主动让助手说晚安』这一步。
  - **根因**:
    - SleepManager._update_runtime_state 在按计划作息时间进入 SLEEPING 时只更新自己内部状态，没有 hook/事件/callback 通知 active_care
    - active_care 已有 is_assistant_goodnight 机制（检测助手说晚安 → 强制进入 reduced_mode），但缺少『主动让助手说晚安』的触发源
    - RitualManager._check_bedtime_ritual 22-23 点的『睡前小结』只走 WebSocket 广播给前端，不会发到 QQ/Telegram 聊天里给用户看到
  - **修复**:
    - active_care_prompts.py 新增 TASK_GOODNIGHT_PROACTIVE_TEMPLATE 模板：1-2 句简短晚安告别，必须包含晚安告别词，禁止提问（你要睡了不该期待回复）
    - prompt_builder.py 在 _build_task_block_dynamic 中添加 goodnight_proactive sys_prompt_type 处理分支
    - 新增 core/services/active_care/goodnight_proactive.py 模块：trigger_character_goodnight 异步发送晚安消息；每日每角色去重；role_id → profile_filename 映射（aveline→core_aveline.json, ling→core_ling.json）；trigger_character_goodnight_async 同步入口供 SleepManager 调用
    - sleep_manager.py 新增 _on_enter_sleeping 方法，在 _update_runtime_state 两处 phase → SLEEPING 的转换点（SLEEP_LATER 到期 + 进入计划睡眠窗口）调用；仅在 prev_phase != SLEEPING 时触发避免重复发送；用 asyncio.ensure_future 异步触发不阻塞状态机
  - **验证**:
    - `venv_core\Scripts\python.exe -m pytest tests/scripts/active_care/verify_character_goodnight.py -v`
    - `venv_core\Scripts\python.exe -m pytest tests/unit/test_life_sleep_wake_route.py tests/unit/test_reply_policy_support.py tests/character_daily/test_character_daily_plan_tool.py -v`
  - **备注**:
    - 自动闭环：发送晚安消息后，下一轮 proactive_checker.perform_check 会调用 intent_detector.extract_latest_assistant_goodnight 检测到，并通过 _try_enter_goodnight_on_intent(is_assistant_goodnight=True) 强制进入 reduced_mode，无需手动维护睡眠会话状态
    - 用户决策：LLM 生成消息内容；用户已主动说晚安时仍发（作为角色视角的告别）；所有角色都触发；纯晚安告别（不含今日总结）
    - 每日去重：同一 role_id 同一天最多发一次，避免 SLEEP_LATER 反复到期或多次 tick 重入导致重复发送

## 2026-07-05（周日）

- **扩展：半夜叫醒后角色睡回去也主动给用户发告别消息**
  - **背景**: 用户反馈：半夜把角色叫醒后，3 分钟静默窗口结束后角色会决策继续熬夜还是睡回去。如果决策是睡回去，也应该给用户发一条消息让他知道角色睡去了，不要无声无息地消失。
  - **根因**:
    - finalize_sleep_recovery_check 的 RETURN_TO_SLEEP 分支只更新 phase=SLEEPING，没有触发 _on_enter_sleeping hook
    - 即使触发了 hook，首次入睡的每日去重会拦住『今日已发过晚安』的睡回去场景
  - **修复**:
    - active_care_prompts.py 新增 TASK_SLEEP_AGAIN_PROACTIVE_TEMPLATE 模板：半夜睡回去场景，发『我先去睡了』类告别，明确要求不再发『晚安』（已发过）
    - prompt_builder.py 添加 sleep_again_proactive sys_prompt_type 处理分支
    - goodnight_proactive.py 重构 trigger_character_goodnight 增加 is_sleep_again 参数：True 时使用 sleep_again_proactive 模板，走冷却去重（5 分钟）而非每日去重；trigger_character_goodnight_async 同步入口也透传 is_sleep_again
    - sleep_manager.py _on_enter_sleeping 增加 is_sleep_again 参数并透传给 trigger；finalize_sleep_recovery_check 的 RETURN_TO_SLEEP 分支调用 _on_enter_sleeping(is_sleep_again=True)
  - **验证**:
    - `venv_core\Scripts\python.exe -m pytest tests/scripts/active_care/verify_character_goodnight.py -v`
    - `venv_core\Scripts\python.exe -m pytest tests/scripts/active_care/verify_character_goodnight.py tests/unit/test_life_sleep_wake_route.py tests/unit/test_reply_policy_support.py tests/character_daily/test_character_daily_plan_tool.py tests/unit/test_qq_adapter_import.py tests/unit/test_adapter_refactor.py -q`
  - **备注**:
    - 场景区分：首次入睡（is_sleep_again=False，每日去重，goodnight_proactive 模板）vs 半夜睡回去（is_sleep_again=True，5分钟冷却去重，sleep_again_proactive 模板）
    - 冷却去重理由：避免短时间内 finalize_sleep_recovery_check 多次触发 RETURN_TO_SLEEP 导致重复发送（虽然 prev_phase 守卫已能拦住大部分情况，但冷却更稳妥）
    - 自动闭环：睡回去消息发出后，下一轮 proactive_checker 仍会通过 extract_latest_assistant_goodnight 检测到并进入 reduced_mode
    - 测试覆盖：13 个测试用例，包括首次入睡、睡回去、冷却去重、不受每日去重限制、hook 透传等场景

## 2026-07-05（周日）

- **新增 QQ /打断 指令，支持忙碌中的角色进入持续聊天窗口**
  - **背景**: 用户已有 `/唤醒` 可以强制叫醒睡觉中的角色，但角色在 `studying` 等 busy 状态下仍会命中 `busy_defer_silent(...)`，必须连发多条消息才会被概率性打断，体验很差。
