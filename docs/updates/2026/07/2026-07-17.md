## 2026-07-17（周五）

- **人物档案系统：known_fact 历史值记录 + 角色人设自动更新 + search_memory 冗余清理**
  - **背景**: 用户反馈角色人设档案完全没被更新（和最开始一样），同时 known_fact 不支持会变的属性（如体重），另外 search_memory 工具里 _search_weighted_memories_direct 与 hybrid_search 功能重叠是历史遗留冗余。
  - **根因**:
    - 提取器只更新人际关系档案（PERSON 类型），不更新角色人设档案（ROLE 类型）
    - KnownFact 模型只有当前值，没有历史值字段，无法记录会变属性的演化轨迹
    - search_memory_tool.py 的 _search_weighted_memories_direct 方法直接扫磁盘 JSON 做纯关键词匹配，与 memory_manager.hybrid_search（向量+关键词）功能高度重叠
    - _format_batch 把所有 assistant 标为 [AI]，LLM 无法区分是 Aveline 还是 Ling 说的
  - **修复**:
    - KnownFact 新增 history: List[Dict] 字段，to_dict/from_dict 同步更新；PersonProfile.add_known_fact 在 value 变化时把旧值 push 到 history（保留旧轨迹），支持体重/年级等会变属性
    - 新增 ROLE_UPDATE_EXTRACTION_PROMPT 和 _extract_role_updates 方法：复用主流程加载的 messages，用单独 prompt 提取 Aveline/Ling 自身偏好/习惯/性格，更新到 default 版本 ROLE 档案的 known_facts
    - _load_chat_history 给每条消息加 _source_role 字段（aveline/ling），_format_batch_with_role 区分 [Aveline]/[Ling] 让 LLM 能区分说话人
    - _call_llm 抽出 _call_llm_with_prompt 公共方法避免重试逻辑重复，_extract_role_updates 复用
    - 删除 search_memory_tool.py 的 _search_weighted_memories_direct 方法（~210 行）及其 jieba 辅助函数（_extract_keywords_jieba / _compute_keyword_match_score / _STOPWORDS / JIEBA_AVAILABLE），search_memory 工具现在只保留 hybrid_search + chat_history 两路来源
    - 删除依赖被删 jieba 函数的 tests/unit/test_search_memory_jieba.py
  - **验证**:
