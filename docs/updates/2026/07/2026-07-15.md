## 2026-07-15（周三）

- **修复晚安消息语义错误：角色说『说了晚安又不睡』而非自己要睡**
  - **背景**: 07-15 23:00 aveline 和 23:30 ling 都生成了『说了晚安又不睡』这种语义错误的晚安消息。这条消息不是角色自己要睡的意思，反而像在指责用户。两个角色生成的内容几乎一样（aveline: 哼，说了晚安又不睡 / ling: 说了晚安又不睡），且都不像角色自己要睡了。
  - **根因**:
    - TASK_GOODNIGHT_PROACTIVE_TEMPLATE 模板只说『你按作息时间准备睡觉了』+『必须包含晚安告别的词』，但没有明确『角色自己要睡』vs『指责用户不睡』的语义边界
    - AVELINE_TONE_REFERENCE 全是『傲娇指责用户不睡』风格（如『哼，又熬夜？去睡觉』『你是不是傻，这个点还不睡』）
    - LLM（MiniMax-M2.5）把『晚安』+『傲娇』+『指责用户不睡』三者融合，自由发挥生成了『说了晚安又不睡』这种语义错误的内容
    - ling 角色虽然用动态 dialogue_examples 而非 AVELINE_TONE_REFERENCE，但 LLM 在两个角色 prompt 下都生成了几乎一样的内容，说明 LLM 训练数据中本身就倾向于这种『晚安探针』表达
  - **修复**:
    - 修改 core/agents/chat_agent_components/persona_system/prompt/active_care_prompts.py 中的 TASK_GOODNIGHT_PROACTIVE_TEMPLATE：加强『你（角色本人）要去睡了』的语义，明确禁止『说了晚安又不睡』『你怎么还不睡』『又熬夜』『这个点还不睡』等指责用户不睡的内容
    - 同步修改 TASK_SLEEP_AGAIN_PROACTIVE_TEMPLATE：加同样的【语义红线】约束，防止睡回去场景也出现类似问题
    - 新增测试用例 test_goodnight_proactive_template_has_semantic_redline：验证两个模板都必须包含『语义红线』『说了晚安又不睡』『指责用户不睡』『角色』等关键约束，防止未来被误删
