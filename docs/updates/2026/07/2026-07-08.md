## 2026-07-08（周二）

- **支持 `/跳过活动` 无需先 `/打断`**
  - **问题**: 必须先 `/打断` 才能 `/跳过活动`，使用不自然
  - **修复**:
    - `/跳过活动` 在无活跃中断窗口时，自动创建窗口并立即标记跳过当前活动
    - 对睡眠/起床过渡态返回提示，要求先 `/唤醒`
    - 空闲状态直接提示不需要跳过
  - **文件**: `routers/v1/life.py`

- **修复 `/跳过活动` 和 `/继续聊` 找不到中断窗口的问题**
  - **问题**: `/打断` 接口会扩展 `conversation_id` 为 `__persona__` 后缀格式，而 `/跳过活动` 和 `/继续聊` 使用原始 `conversation_id`，导致找不到窗口
  - **修复**:
    - 新增 `_normalize_conversation_id_for_interrupt()` 函数，在跳过/延长接口中对齐 `/打断` 的 conversation_id 格式
    - 为 `ActivitySkipRequest` 和 `ActivityExtendRequest` 添加 `profile_filename` 字段，支持正确解析 role_id
  - **文件**: `routers/v1/life.py`

- **中断窗口结束时的主动消息机制**
  - **问题**: 窗口结束时 AI 没有主动发消息告知用户「回去做事了」
  - **修复**:
    - 新增 `interrupt_window_proactive.py` 模块，处理窗口结束时的主动消息
    - `InterruptWindowManager` 新增 `get_expiring_windows()` 方法获取即将过期的窗口
    - `CharacterDailyEngine._tick()` 中添加检查逻辑，窗口剩余 ≤ 60 秒时触发主动消息
    - 通过 `ending_notified` 标记避免重复发送
  - **文件**:
    - `core/services/character_daily/interrupt_window.py`
    - `core/services/character_daily/interrupt_window_proactive.py`
    - `core/services/character_daily/engine.py`

- **`/help` 指令改为动态同步，从 CommandRouter 获取指令列表**
  - **问题**: `/help` 指令列表是硬编码的，后端指令修改后不会自动同步
  - **修复**:
    - `CommandRouter` 新增 `get_command_list()` 方法，返回所有注册的指令
    - `SystemHandler.show_help()` 改为从 `CommandRouter` 动态获取指令列表
    - 新增 `_COMMAND_DESCRIPTIONS` 字典维护指令描述
    - 新增指令时只需修改 `_COMMAND_DESCRIPTIONS` 和 `_build_routes()`
  - **文件**: `clients/bots/handlers/command_router.py`, `clients/bots/handlers/system.py`

- **打断窗口改进：窗口结束提示、跳过活动、延长窗口**
  - **问题**: 用户使用 `/打断` 命令打断角色后，窗口结束时没有消息提醒用户，且 AI 无法调整计划跳过学习任务
  - **修复**:
    - 窗口即将结束时（剩余 <= 60 秒），AI 会自然提及「差不多该回去做事了」
    - 新增 `/跳过活动` 命令：用户可以让 AI 跳过当前学习任务，专心聊天，不再提醒回去做事
    - 新增 `/继续聊` 命令：用户可以延长聊天窗口时间（最多 3 次）
    - 新增 API：`/api/v1/life/activity/skip` 和 `/api/v1/life/activity/extend`
  - **文件**:
    - `core/services/character_daily/reply_policy_support.py`
    - `core/services/character_daily/reply_policy.py`
    - `core/services/character_daily/interrupt_window.py`
    - `routers/v1/life.py`
    - `clients/bots/handlers/command_router.py`
    - `clients/bots/handlers/command_router_session_support.py`

- **修复WebSocket连接状态检查**
  - **背景**: WebSocket连接在accept后可能被客户端快速断开，导致receive_json时抛出 'WebSocket is not connected' 错误
  - **根因**:
    - 客户端在accept后立即断开连接，服务端来不及检查状态就调用receive_json
    - 原代码对RuntimeError异常没有特殊处理，直接作为错误抛出
  - **修复**:
    - 在消息循环中添加WebSocket client_state检查，非CONNECTED状态时跳出循环
    - 添加专门的RuntimeError异常处理，将 'WebSocket is not connected' 类错误作为正常断开处理
  - **验证**:
    - `ruff check adapter.py`
  - **备注**:
    - 修改文件: core/interfaces/websocket/adapters/adapter.py
    - 错误日志级别从ERROR降为INFO，减少无效告警
