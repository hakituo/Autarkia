## 2026-07-02（周四）

- **修复 Active Care 手动延迟期间仍按约十分钟提前唤醒**
  - **背景**: 用户反馈 Active Care 在日志中已经显示 `next_in=16万秒` 级别的手动延迟，但主循环仍每隔约 9~11 分钟醒一次，并重复输出双 QQ 的旧消息跳过日志。
  - **根因**:
    - ProactiveLoopRunner.calculate_sleep_interval() 只把 manual_delay 当成“本轮不做主动决策”，没有把它用于主循环的实际睡眠时长，因此仍会被 dynamic_interval 提前唤醒。
    - UserResponseHandler 对旧用户消息的去重只使用单个全局签名，双 QQ 模式下两个 persona 会互相覆盖，导致每次被提前唤醒时都会重复打印旧消息跳过日志。
  - **修复**:
    - 在 proactive_loop.py 中，当 checker.last_skip_reason 为 `manual_delay` 且 next_decision_ts 仍在未来时，主循环直接睡到该决策时间，而不是继续沿用动态间隔。
    - 在 service.py 中把 `_last_processed_user_msg_signatures` 调整为按 persona 存储的字典状态。
    - 在 user_response_handler.py 中按 persona 生成独立去重 key，避免双 QQ 之间互相覆盖旧消息签名。
    - 补充 `tests/unit/test_active_care_due_reminder_and_loop.py`，覆盖 manual_delay 长等待直接睡眠与双 QQ 旧消息去重隔离两类回归场景。
  - **验证**:
    - `venv_core\Scripts\python.exe -m pytest tests\unit\test_active_care_due_reminder_and_loop.py -q`
  - **备注**:
    - 这次修复改变的是主循环调度行为，不只是日志降噪；新的用户消息、提醒或外部唤醒事件仍可通过 wakeup_event 提前打断睡眠。

    - 把 DailySummary 解析辅助逻辑拆到 `core/services/journal/summary_parse_support.py`，优先解析完整对象，失败后再从原始文本中回收 `date/summary/stats/tomorrow_tone`。
    - 更新 `core/services/journal/summary_service.py`，改用新的稳健解析入口，并把月总结日期截止判断改成 `date()` 级别比较，彻底避开 aware/naive 直接比较。
    - 补充 `tests/unit/test_journal_summary_parse_support.py` 单测，并扩展 `tests/scripts/journal/verify_daily_summary_json_parser.py` 与 `tests/scripts/journal/verify_daily_summary_timezone_fix.py` 覆盖坏 JSON 与月末时区回归场景。
