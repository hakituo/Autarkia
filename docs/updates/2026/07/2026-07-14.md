## 2026-07-14（周二）

- **起床提醒被跳过时自动标记对应计划项为完成**
  - **背景**: Active Care 检测到起床提醒到期、但用户已经起床（last_goodmorning_ts>0）时，只调用了 complete_reminder 标记 reminder 消息完成，没有把对应的 PlanItem（如「起床洗漱+早餐」）标记为 completed。导致计划视觉上没勾上，且 end_reminder 仍会触发，让用户起床后还收到「该休息了」的奇怪消息。
  - **根因**:
    - checker_event_handler.py 的起床提醒跳过分支只调用 complete_reminder，未联动 JournalService.mark_plan_item_status
    - _defer_due_reminder 的起床分支同样只 complete_reminder，未清理对应 PlanItem 和 end_reminder
  - **修复**:
    - 新增 _auto_complete_wakeup_plan_item 辅助方法：从 reminder.metadata 读取 plan_item_id/plan_date，调用 JournalService.mark_plan_item_status 标记 completed，并一并 complete 掉 end_reminder
    - handle_due_reminder 起床提醒跳过分支在 complete_reminder 后调用该辅助方法
    - _defer_due_reminder 起床分支在 complete_reminder 后同样调用该辅助方法
    - 所有异常吞掉只记日志，不影响主流程
  - **验证**:
    - `venv_core\Scripts\ruff.exe check core\services\active_care\checker\checker_event_handler.py`
  - **备注**:
    - 修改文件: core/services/active_care/checker/checker_event_handler.py
    - 涉及模块: Active Care + Journal Plan 系统

## 2026-07-14（周二）

- **活动自然切换时的告别消息：角色从可聊天切到忙碌/睡觉时主动发告别话**
  - **背景**: 用户跟角色聊天时，到了下一个计划时段（学习/做饭/睡觉），角色不会主动说告别话，直接消失或只触发固定晚安消息，聊得好好的突然就睡了，很不自然。build_plan_transition_persona_hint 只在用户发消息时注入提示且只在 5 分钟窗口内生效，engine._tick 不触发主动消息，schedule_activity_return 只在 /打断 接口调用时才安排告别消息。
  - **根因**:
    - build_plan_transition_persona_hint 只在用户发消息时注入提示，且只在 plan_transition_notice_seconds（300秒）窗口内生效
    - engine._tick 的 sync_current_activities 只更新 plan.current_activity，不触发任何主动消息
    - schedule_activity_return 只在 /打断 接口和 /延长 接口调用时才安排告别消息
    - trigger_character_goodnight 用固定晚安模板，不考虑当前是否在聊天
  - **修复**:
    - 新建 core/services/character_daily/activity_transition.py 模块：检测活动切换方向（to_busy/to_sleep/none）+ 检查用户是否在聊天（300秒窗口）+ 去重检查（60秒冷却）+ 发送告别消息
    - 修改 engine.py 的 _tick：sync_current_activities 前记录 prev_activities，sync 后检测活动切换并调用 check_and_send_farewell_on_transition
    - 修改 goodnight_proactive.py：新增 _is_user_in_conversation 函数，trigger_character_goodnight 首次入睡时检查用户是否在聊天，如果在聊天用 build_sleep_during_chat_farewell_instruction 让 LLM 判断是顺延还是告别去睡
    - 修改 activity_return/instruction.py：新增 _ACTIVITY_START_FAREWELL_TEMPLATE 和 _SLEEP_DURING_CHAT_FAREWELL_TEMPLATE 两个模板，以及对应的 builder 函数
    - config/character_daily_config.py 新增 activity_transition_farewell_enabled / activity_transition_user_active_seconds / activity_transition_farewell_cooldown_seconds 三个配置项
    - 对 SLEEPING 切换在 activity_transition 中返回 none，交给 sleep_manager._on_enter_sleeping → trigger_character_goodnight 实时处理，避免重复发送
  - **验证**:
    - `venv_core\Scripts\python.exe -m pytest tests\scripts\character_daily\verify_activity_transition.py -v（23 个测试全部通过）`
    - `venv_core\Scripts\python.exe -m pytest tests\scripts\character_daily\verify_activity_return.py -v（15 个测试全部通过）`
    - `venv_core\Scripts\python.exe -m pytest tests\scripts\active_care\verify_character_goodnight.py -v（13 个测试全部通过）`
    - `venv_core\Scripts\python.exe -m ruff check（代码规范检查通过）`
  - **备注**:
    - 覆盖场景：用户在休息时间跟角色聊天到了学习时间 → 角色主动说我要去学习了
    - 覆盖场景：用户在聊天到了睡觉时间 → 角色判断是顺延还是告别去睡（不再突然发晚安）
    - 覆盖场景：用户没在聊天时活动切换 → 不发告别消息（不打扰）
    - SLEEPING 切换由 sleep_manager 实时触发 trigger_character_goodnight，比 engine._tick（2分钟一次）更及时
