## 2026-07-11（周五）

- **重构 LifeSimulationService：拆分协调器层**
  - **背景**: `LifeSimulationService` 承担了硬件监控、角色管理、食物系统、自动进食、健康监控、生命状态、睡眠管理、仪式管理、反应管理、WebSocket 广播、情绪影响、每日总结等 12+ 个职责，代码近 532 行，严重违反单一职责原则。
  - **重构方案**: 引入 Orchestrator + Coordinator 分层架构
    - `LifeSimulationService` → 轻量级门面（295 行），委托全部逻辑到 `LifeOrchestrator`
    - `LifeOrchestrator` → 总协调器（415 行），管理子模块初始化、主循环、每分钟 tick、状态构建
    - 6 个专职协调器，各管一域：
      - `HardwareCoordinator` → 硬件状态采集与阈值检测
      - `ActorCoordinator` → 角色状态与关系管理
      - `FoodCoordinator` → 食物库存、消化与自动进食
      - `SleepCoordinator` → 睡眠状态查询与中断通知
      - `ReactionCoordinator` → 仪式触发与自发反应
      - `WebSocketCoordinator` → 状态广播
  - **兼容性**: 外部 API 完全兼容，28 个公开方法 + 16 个属性保持不变，外部调用者零修改
  - **新增文件**: `coordinators/` 目录（6 个协调器 + `__init__.py`）、`orchestrator.py`
  - **修改文件**: `service.py`（532→295 行）、`__init__.py`（新增导出）
