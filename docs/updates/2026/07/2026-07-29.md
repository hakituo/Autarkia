## 2026-07-29（周二）

- **四项算法升级：艾宾浩斯衰减 + sigmoid 召回 + Equal Jitter 退避 + Bandit 闭环**
  - **背景**: 记忆系统和主动关怀模块原有算法偏工程启发式（分段台阶、uniform 基础项、固定指数退避），存在数学建模硬伤；ε-greedy 多臂老虎机只有 select 没有 update，从未真正学习
  - **根因**:
    - recall_probability.py 时间衰减用分段台阶（1h 和 23h 给同一分），不连续
    - recall_probability.py 召回概率用 uniform(0,0.9) 当基础项，抹掉权重差异
    - calculate_non_response_backoff 用 min(1.8^n, 12) + ±10% jitter，方差小、模式可预测
    - select_action_bandit 读取 policy_scores 但无人调用 save_policy_scores，bandit 退化为完全随机 + LLM 兜底
    - DEFAULT_BANDIT_EPSILON 常量定义了却未被引用
  - **修复**:
    - recall_probability.py：时间衰减改为艾宾浩斯幂律 R=(1+t/τ)^(-β)，τ=24h β=0.85，1h≈0.94 / 1d≈0.55 / 1w≈0.20 / 1mo≈0.10
    - recall_probability.py：召回概率改为 sigmoid 融合，logit 空间组合 weight/relevance/recency，σ 压回 [0,1]
    - scoring_utils.py::score_recent_hit 同步用幂律衰减（τ=1h β=0.5）
    - constants.py::calculate_non_response_backoff 改为 AWS Equal Jitter max(1.0, expo/2 + uniform(0, expo/2))，方差从 5% 提升到 25%
    - storage.py 新增 update_policy_reward(action, reward) 方法，增量平均 avg_new = avg_old + (reward-avg_old)/count
    - user_response_handler.py 新增 _reward_last_action(reward=1.0)，用户响应时给上次动作发正奖励
    - message_dispatcher.py 首次无响应时给上次动作发 reward=-1.0，避免连续无响应过度惩罚
    - decision.py select_action_bandit 引用 DEFAULT_BANDIT_EPSILON 常量
  - **验证**:
    - `tests/scripts/algorithm_upgrade/verify_algorithm_upgrade_2026_07_29.py 4/4 通过`
    - `TEST 1 时间衰减连续性：单调递减、无分段跳变、关键节点值符合预期`
    - `TEST 2 sigmoid 召回：高权重 1000/1000、低权重 45/1000、随权重单调递增`
    - `TEST 3 Equal Jitter：下界保护 ≥1.0、均值 ≈0.75*expo、方差显著、cap 保护 ≤12.0`
    - `TEST 4 Bandit 闭环：update_policy_reward 增量平均正确、趋近期望、磁盘持久化、分值排序正确`
  - **备注**:
    - 设计原则：不引入需要数学推导的复杂算法，只把硬编码阈值参数化
    - 保持向后兼容：硬性保留规则（is_important/preference）仍直接通过过滤
    - 失败静默：奖励闭环异常不阻塞主流程
