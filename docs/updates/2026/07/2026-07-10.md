- **修复 QQ adapter 长时间运行后重启后端不自动重连**
  - **背景**: QQ adapter 运行较长时间后，重启后端，QQ adapter 不会自动重连，必须两者同时重启才能连上。根因是连接循环的 finally 块异常泄漏导致 task 静默死亡，且监控器无法检测死 task。
  - **根因**:
    - connection.py finally 块中 await receive_task 只 catch CancelledError，receive_task 完成时抛出的 ConnectionClosed 等异常会泄漏，导致连接循环 task 静默死亡
    - 内层 except Exception 吞掉异常不 re-raise，session.ws 不清理，外层重连逻辑可能不被触发
    - monitor.py 只检查 session.running 标志，不检查 task.done()，task 死亡后 running 仍为 True 导致监控器无法检测
    - monitor.py ws 断开时需等 120 秒超时才重启，太慢
  - **修复**:
    - connection.py finally 块改为 catch BaseException，彻底防止异常泄漏
    - connection.py 内层 except Exception 改为 set session.ws=None + re-raise，确保外层重连逻辑被触发
    - connection.py 添加顶层 try-finally，loop 退出时强制 running=False，让监控器能检测到
    - monitor.py 新增 _is_task_dead() 检查 task.done() && running=True，30 秒内检测死 task 并重启
    - monitor.py 新增 _is_ws_closed() 安全检测 ws 关闭状态，ws 断开时给予 10 秒宽限期让连接循环自行重连
