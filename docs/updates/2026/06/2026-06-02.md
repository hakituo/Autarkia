## 2026-06-02 修复 resolve_persona_prompt 全局单例污染导致跨人设 prompt 写入错误 scope 记忆

2. **context.py**: 调用 `_resolve_persona_prompt()` 时传入 `profile_filename`
3. **chat_agent.py**: `_get_dynamic_system_prompt()` 新增 `profile_filename` 参数并透传

## 2026-06-02 修复双角色对话系统上下文串线和Active Care时间同步问题

### 问题1：聊天记录串角色
Aveline和Ling的聊天记录互相串，Aveline会把和Ling的聊天记录当成和主人的聊天记录。

根因：
1. `conversation_labels.py` 和 `data_paths.py` 中 `default_user` 的 `storage_scope` 依赖全局 `_resolve_scope_from_active_persona()`，切换 persona 时存储路径跟着变
2. `chat_history_store.py` 的 `list_conversation_events` 搜索所有4个 scope 目录，跨角色记录合并
3. `context.py` 的 `_is_candidate_matching_current_persona` 对 `default/default_user` 总是返回 True

### 问题2：Active Care 两个角色同时触发
Aveline和Ling的 active care 触发时间完全相同，没有差异化。

根因：
1. `ProactiveChecker` 只有单一 `next_decision_ts`，两个 persona 共享
2. 双QQ模式串行执行时后一个 persona 覆盖前者的时间
3. `on_assistant_message_sent` 统一更新所有 persona 的时间戳

### 修复
- **proactive_checker.py**:
  - `next_decision_ts` 和 `_next_llm_decision_ts` 改为 per-persona 字典 `_next_decision_ts_by_persona`
  - `set_next_decision_ts` 增加 `profile_filename` 参数，只更新对应 persona 的时间戳
  - 新增 `_get_earliest_next_decision_ts()` 计算所有 persona 中最早的时间戳
  - 新增 `get_next_decision_ts_for_persona()` 查询特定 persona 的下次决策时间
  - 双QQ模式下每个 persona 独立检查自己的 `next_decision_ts`，未到时间的跳过
  - `initialize()` 恢复 per-persona 的时间戳
  - 所有 `set_next_decision_ts` 调用点传入 `profile_filename`

- **service.py**:
  - `on_assistant_message_sent` 增加 `profile_filename` 参数
  - 有 `profile_filename` 时只更新对应 persona 的 `_last_trigger_ts_by_persona` 和 `next_decision_ts`
  - 无 `profile_filename` 时保持原有行为（更新所有）

- **context.py**:
  - `_is_candidate_matching_current_persona` 对 `default/default_user` 返回 False 而非 True

- **conversation_labels.py**:
  - `default_user` 和 `default` 的 `storage_scope` 固定为 `"user"`，不再依赖全局 persona 状态

- **data_paths.py**:
  - `resolve_data_scope_from_conversation_id` 对 `default/default_user` 等固定返回 `"user"`

- **chat_history_store.py**:
  - `list_conversation_events` 优先在 conversation_id 对应的 scope 目录搜索
  - 只有在主目录找不到时才 fallback 到其他目录

## 2026-06-02 用户学习画像改为工具调用

### 背景
用户学习画像之前是每次对话自动注入到 prompt 中，无论是否需要都会消耗 token。改为工具（`get_study_profile`），AI 需要时才调用。

### 修改内容
1. **新增 core/tools/study_profile_tool.py**: `GetStudyProfileTool` 工具类，支持按学科查询学习画像
2. **core/tools/registry.py**: 注册 `GetStudyProfileTool`
3. **context_persona.py**: `prepare_active_tools()` 新增学习相关关键词激活 `get_study_profile`
4. **components.py**: `build_study_context()` 移除 `_load_study_profile_brief()` 调用，仅保留 study_mode 实时状态；删除已无用的 `_load_study_profile_brief()` 函数

### 保留
- study_mode 下的实时学习状态（背单词进度等）仍自动注入，因为这是即时上下文
- Active Care 的 `build_study_context_for_active_care()` 不受影响
