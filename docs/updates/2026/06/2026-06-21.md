- **🔧 拆分 `core/image/image_manager.py`（1226行 → 7 个文件，全部 < 500 行）**
  - 原因：原 `image_manager.py` 单文件 1226 行，远超 Python 单文件 500 行限制，且职责混杂（资源协调+GPU切换+Forge后端+ComfyUI后端+SiliconFlow云端后端+模型查询+生命周期+单例）
  - 拆分结果（Mixin 模式薄壳门面，保持外部 API 完全兼容）：
    - `core/image/image_manager.py`（264行）：薄壳门面，保留 `ImageManager` 类定义（多继承 5 个 Mixin）、`__init__`/`_ensure_output_dir`/`initialize`/`shutdown`/`generate_image`/`generate_images`、全局单例 `get_image_manager`/`shutdown_image_manager_instance`，并重导出 `ImageGenerationConfig`
    - `core/image/_image_config.py`（39行）：`ImageGenerationConfig` 配置类（独立，无依赖）
    - `core/image/_image_resource_mixin.py`（176行）：`_ImageResourceMixin` — 资源协调/GPU 切换/Forge 卸载调度，包含 `_restore_llm_gpu`/`_set_image_gen_active`/`_begin_image_gen`/`_end_image_gen`/`_cancel_pending_forge_unload`/`_schedule_forge_unload_if_needed`
    - `core/image/_image_forge_backend_mixin.py`（421行）：`_ImageForgeBackendMixin` — Forge 进程管理 + 图像生成，包含 `_is_forge_ready`/`_start_forge_process`/`_terminate_forge_process`/`_ensure_forge_ready`/`_warmup_forge_api`/`_generate_with_forge`
    - `core/image/_image_comfy_backend_mixin.py`（266行）：`_ImageComfyBackendMixin` — ComfyUI 后端（Flux/SDXL + Nunchaku/Lightning/Turbo/LCM 加速），包含 `_generate_with_comfy`
    - `core/image/_image_cloud_backend_mixin.py`（95行）：`_ImageCloudBackendMixin` — SiliconFlow 云端后端，包含 `_generate_with_siliconflow`

  - 设计选择：采用 **Mixin 模式** 而非委托模式。理由：(1) 方法体完全不变（严格满足"whole methods"原则）；(2) self 属性访问照常无需修改（mixin 方法在 ImageManager 实例上调用，self 即 manager 实例，等价于"把 manager 整体注入"）；(3) 外部 API 完全兼容（ImageManager 还是那个类，MRO 正确）；(4) 改动最小最安全（正确性优先）
