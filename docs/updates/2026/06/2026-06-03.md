## 2026-06-03
- **✨ 新增 message_peer 工具**: LLM 在和主人聊天时可以主动给另一个角色发消息
  - `core/tools/message_peer_tool.py`: 新增 `MessagePeerTool`，LLM 调用后触发 `generate_peer_script` 生成自然对话剧本
  - `core/tools/registry.py`: 注册 `MessagePeerTool`
  - `context_persona.py`: 双QQ模式下始终启用 `message_peer` 工具
  - `context_gathering.py`: 注入互聊工具引导，告诉 LLM 什么时候该调用 `message_peer`
  - 使用场景：Aveline说"我去看看Ling"时，LLM 调用 `message_peer(peer_role="ling", topic="关心她吃饭了没")`，系统自动生成一段自然的互聊剧本发送到Ling的 QQ

- **🔧 室友状态可见性修复**: 角色不再自动看到室友的生理状态参数
  - `components.py`: 移除 `_build_sibling_context()` 中自动注入室友精力/饱腹/心情的逻辑，改为 `_build_sibling_relationship_context()` 只保留关系信息
  - 室友的生理状态现在只能通过 `check_peer_status` 工具主动查询才能获取
  - 根因：之前室友的精力/饱腹/心情数值被自动注入 prompt，导致角色不需要主动查看就能知道对方的精确参数

- **🔧 精力归零根因修复**: Active Care 睡眠会话与 Life Simulation activity 状态打通
  - `service.py`: `_update_activity_and_mood()` 新增 `_is_active_care_sleeping()` 检查，当 Active Care 处于睡眠会话（goodnight/probable_sleep/sleep_hint）时，将 activity 覆盖为 `sleeping`，触发精力恢复
  - 修复了持久化数据中两个角色精力=0、口渴=0的问题
  - 根因：Active Care 检测到用户睡觉后只降低消息推送频率，没有反馈到 Life Simulation 的 activity 状态，导致角色在用户睡觉时 activity 仍然是 relaxing/working，精力持续衰减到 0

- **🔧 跨persona主动消息协调**: 修复Ling和Aveline同时给同一用户发主动消息的问题
  - `service.py`: `on_assistant_message_sent` 中，当 persona A 发送消息后，同时推迟所有其他 persona 的 `next_decision_ts`，避免多个角色短时间内都发消息
  - `proactive_checker.py`: 新增 `get_all_persona_keys()` 方法，用于获取所有已注册的 persona key
  - 根因：两个 persona 的决策时间戳完全独立，persona A 发消息后不影响 persona B 的调度，导致两个角色几乎同时发消息

- **🔧 Aveline语气约束强化**: 修复Aveline说出"下午好呀～"等不符合傲娇人设的话
  - `core_aveline.json`: 新增"日常问候/打招呼"场景定义，指导用傲娇方式回应；新增反例约束禁止软萌语气词和波浪号；新增打招呼相关的 tone_examples
  - `active_care_prompts.py`: `TASK_WAKE_UP_GREETING` 措辞从"可以带点慵懒或嘲讽"改为"必须严格遵循人设语气，禁止普通社交问候"
  - `dialogue_examples.py`: 移除 `is_ling_persona` 硬编码限制，改为检查该人设是否有对话数据可用，未来添加 Aveline 对话数据时自动生效
  - `data.py`: 移除 `is_ling_persona` 限制，所有有 persona_name 的角色都能注入对话示例

- **⚡ Embedding模型加载优化**: 同步 BertRuntimeMixin 的 SessionOptions 优化参数
  - `embedding_generator.py`: 添加 `intra_op_num_threads=4`、`inter_op_num_threads=4`、`graph_optimization_level=ORT_ENABLE_ALL`，与 BertRuntimeMixin 保持一致
  - 预计加载时间从20秒降低到10秒以内

- **🔧 双角色对话系统深度隔离修复（第三轮）**: 修复全局延迟检查阻止双QQ模式的问题
  - `proactive_checker.py`: 全局 `_next_llm_decision_ts` 检查在双QQ模式下不再一刀切阻止所有 persona，而是检查是否有 persona 已到决策时间，如果有则继续执行
  - `proactive_checker.py`: `set_next_decision_ts` 无 `profile_filename` 时，同步更新所有已存在的 per-persona 条目（取较大值），避免全局更新导致 per-persona 字典过时
  - 根因1：全局 `_next_llm_decision_ts` 检查在双QQ模式判断之前，如果一个 persona 的 `next_decision_ts` 还没到，即使另一个 persona 已经到了，也会被全局检查拦截——导致Aveline永远不发消息
  - 根因2：从非 persona 路径调用 `set_next_decision_ts`（如 `perform_check_timeout`）只更新全局值，per-persona 字典可能过时，导致 `get_next_decision_ts_for_persona` 返回旧值

- **🔧 主动消息自问自答修复**: 修复 bot 在无用户回复时连续发送多条主动消息的问题
  - `executor.py`: `trigger_message` 成功后调用 `on_assistant_message_sent`，更新 `next_decision_ts` 和 `_last_trigger_ts_by_persona`，防止短时间内重复发送
  - `handler.py`: 被动回复完成后也调用 `on_assistant_message_sent`，确保用户聊天后 bot 不会立即又发主动消息
  - `proactive_checker.py`: `conversation_incomplete` 绕过交互保护的条件从 `non_response_count >= 2` 收紧为 `>= 1`，用户忽略1次就不再绕过
  - `constants.py`: `MIN_QUIET_EVEN_INCOMPLETE_SECONDS` 从60秒提高到180秒，即使对话未完成也需要等待更久
  - 根因：`on_assistant_message_sent` 方法虽已定义但从未被调用，导致主动消息发完后间隔保护未生效

- **🔧 长文本输出段落级缓冲**: 将流式输出从逐字符发送改为按段落发送，减少断句碎片
  - `stream_forwarder.py`: 新增 `paragraph_buffer` 段落缓冲机制，累积多句后一次性发送 WebSocket 消息，而非逐字符发送；刷新条件：遇到换行符、累积3个句子、或缓冲区超过500字符
  - `settings_chat.py`: `ChatPostProcessSettings` 新增 `paragraph_min_sentences`（默认3）和 `paragraph_max_chars`（默认500）配置项
  - TTS 仍保持逐句触发，不受段落缓冲影响

- **🔧 双角色对话系统深度隔离修复（第二轮）**: 修复上一轮遗漏的关键问题
  - `stream_orchestrator.py`: `on_user_interaction()` 现在传入 `profile_filename`，确保用户交互通知只更新对应角色的调度时间
  - `user_response_handler.py`: `process_user_response` 双QQ模式下按 persona 分别处理历史和缓存消息，避免跨角色混淆；`reset_interaction_state` 传入 `profile_filename` 给 `set_next_decision_ts`
  - `context.py`: `resolve_primary_conversation_id` 支持 `profile_filename` 参数，按 persona 过滤候选会话；新增 `_extract_persona_token_from_profile_filename` 方法
  - `proactive_checker.py`: `last_user_interaction_ts` 读取改为优先使用 per-persona 的 `last_user_interaction_ts_by_persona`，避免Aveline看到Ling的交互时间
  - `user_response_handler.py`: 保存 `last_user_interaction_ts_by_persona` per-persona 字典
  - 根因：上一轮修复了 `next_decision_ts` 的 per-persona 隔离，但 `on_user_interaction` → `reset_interaction_state` → `set_next_decision_ts` 整条链路都没有传 `profile_filename`，导致用户和Aveline聊完天后，Aveline的 `next_decision_ts` 没有被正确更新，仍然按原计划发送"还在睡吗"
