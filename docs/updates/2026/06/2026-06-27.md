- **🔌 WebSocket 死锁导致 QQ Adapter 反复断连（"no close frame received or sent"）**
  - **背景**: QQ Adapter 日志显示每 10-20 分钟一次 `Receive error: no close frame received or sent`，连接断开后走指数退避重连。日志中"准备发送消息 - 类型: pong"之后无限挂起，没有"消息发送完成"对应日志
  - **根因**: [websocket_manager.py](file:///d:/AI/xiaoyou-core/core/interfaces/websocket/websocket_manager.py) 的 `handle_heartbeat` 在 `async with self.connections_lock:` 临界区内调用 `send_to_client` → `send_with_retry`，而 `send_with_retry` 又要 `async with self.connections_lock:` ——asyncio.Lock 非重入，自死锁。死锁后接收循环冻结，心跳检查器也拿不到锁，连接最终被 OS / websockets 库以 1006 / "no close frame" 关闭
  - **同源问题**: `handle_message` 重复消息分支也在持锁状态下调用 `send_to_client` 发送 `duplicate_message`，同样的死锁模式
  - **修复**: 两处发送动作移出锁临界区，先在锁内用 `should_send_pong` / `is_duplicate` 标志位记录意图，锁外再调用 `send_to_client`

- **📱 侧边栏手势呼出：放弃全屏覆盖方案，改回窄手势条**
  - **背景**: v4（`awaitEachGesture` + `awaitHorizontalDragOrCancellation`）和 v5（`detectHorizontalDragGestures`）全屏覆盖方案都导致子菜单点击失效、Pager 左滑切 tab 失效。

    - `Box(Modifier.width(32.dp).fillMaxHeight().offset(x = 24.dp).pointerInput(Unit) { detectHorizontalDragGestures(...) })`
    - 只覆盖左边缘 24-56dp 区域，其他区域（56dp 以右）的点击、左滑、垂直滚动都不受影响
    - 24dp 以左不覆盖，留给系统全面屏返回手势
  - **trade-off**: `drawerState.open()` 是固定动画，无法跟手指（Material3 1.3.2 中 `animateTo` 是 private，`dispatchRawDelta` 不公开）
