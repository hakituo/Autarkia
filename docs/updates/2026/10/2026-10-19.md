- **已读不回补回带上「隔了多久」：几小时后想起来再回的语气才对**
  - **背景**: TT 的真实行为是「当时看到懒得回，过几个小时想起来再补一句」，而不是永久不回。实测发现补回链路虽然排程正确，但生成补回文案时模型看不到条目时间：几小时前的中午分享，晚上补回还在说「中午不用纠结吃啥」；用户重新发消息时也只是照常接话，容易把旧话题当成正在发生。
  - **根因**:
    - hints.build_revisit_context 只把消息正文拼进情境提示，条目里的 ts 没有参与投影，模型无从判断「这条是 3 小时前发的」。
    - 补回模板只写了「别解释晚回」，没写「隔久了按现在的状态接、别把几小时前当成正在发生、别一上来追问细节」。
    - 真实记录里「短期不回」的分布此前没有量化口径：按条统计 2026-09 共 1535 条用户消息，1 分钟内回 55%、1-10 分钟 35%、10 分钟-1 小时 3.3%、1-3 小时 2.5%、3-12 小时 3.3%、次日 0.4%，即 >10 分钟才回 9%。
  - **修复**:
    - hints.build_revisit_context 新增 elapsed 段：按条目的 ts 与当前时间输出「这条是 X 分钟前 / 约 X 小时前 / 隔了一天前发的」，10 分钟内不提示（避免干扰即时对话）。
    - 补回模板补两条约束：隔了一段时间就按现在的状态接，不把几小时前的事当成正在发生；不要一上来就追问细节。仍保留 [SKIP] 兜底。
    - build_revisit_context 新增可选 now 参数，只给测试固定时钟用；生产不传，走真实时间。

    - `tests/character_daily 全量 194 passed（含 test_read_no_reply_store 的 [SKIP] 与文案断言）`

- **补上「隔几分钟才回」这一档：TT 的回复节奏从 91% 秒回降到 59%**
  - **背景**: TT 的真实节奏是三段：1 分钟内回 55%、1-10 分钟回 35%、10 分钟以上或次日 9.5%、始终没回 0%。系统改前只有两段——立刻回 91% 或进已读不回队列（10 分钟起），中间那 35% 的「隔几分钟才看到」完全缺失，所以体感是「要么秒回、要么半天不理」。
  - **根因**:
    - read_no_reply 只有 silent / revisit 两种结果，revisit 延迟下限固定 600 秒，没有人不在手机边时的分钟级延迟档。
    - reply_policy 的轻活动软延迟 quick 档只有十几秒，且只在特定活动命中，空闲状态直接走「立即回复」。
    - 已读不回缺少「到点了还是不想接」的放弃开关，只能靠模型输出 [SKIP]，而实测 24 次采样一次都没触发。
  - **修复**:
    - 新增 idle_short_delay 三件套（probability / min / max）：空闲时按概率延迟 60~180 秒再回，走 is_soft_delay 合并批，等待期内的新消息并入同一批回复。判定放在轻活动软延迟之前。
    - 新增 revisit_skip_probability（默认 0）：到点补回前再抽一次「想起来了还是不想接」，命中则清条目、不补回。默认 0 是因为真实记录里始终没回为 0 条。
    - 新增 build_idle_short_delay_hint：只给「人不在手机边」的状态事实，不写「刚看到」「刚在忙」这类借口。
    - character_runtime.yaml 给 TT 打开 idle_short_delay_probability=0.35、60~180 秒。
  - **验证**:
    - `蒙特卡洛（2026-09 真实 1535 条消息 × 200 次）：改前 立即 90.9% / 1-10 分钟 0% / 10 分钟以上 5.3% / 不回 3.8%；改后 59.1% / 31.9% / 5.2% / 3.8%，与真实 55.1% / 35.4% / 9.5% / 0% 基本对齐`
    - `tests/character_daily 198 passed（新增 4 个：短期延迟命中/关闭、补回放弃命中/未命中）`
    - `tests/unit 5759 passed / 10 failed（9 个为既有基线：cross_platform_paths 7、journal 标点 1、study 路径 1；新增 1 个 test_model_settings_defaults 期望 temperature=0.7 而 modeling.yaml 为 1.1，与本次改动无关）`

    - 全量 pytest 约 76 秒（tests/unit 56.7s + 其余 19.3s），不是死锁；上次命令把输出过滤成只看结尾，中间没有进度条，看起来像卡住。
