## 2026-10-22（星期四）

- **新增 fetch_url 工具：网址走抓取、关键词走搜索**
  - **背景**: 用户反馈让 AI 打开 https://example.icu 时始终访问不到，而 DeepSeek 网页端能正常查看该站。实测站点本身返回 200 且正文为服务端直出，排查发现工具链只有 web_search，没有按网址读正文的能力。
  - **根因**:
    - 工具链只有 web_search，把查询交给搜索 API，返回的是引擎生成的 summary/snippet，不是页面正文
    - 模型把整条 URL 当搜索关键词，搜索引擎只返回关于该域名的第三方 SEO 页面
    - 站点尚未被搜索索引收录，site: 查询同样无结果，换关键词也搜不到
  - **修复**:
    - 新增 core/tools/web_fetch/（tool.py + extract.py），实现 fetch_url：aiohttp 抓取、标准库 HTMLParser 抽正文、剔除脚本样式、合并重复行、按字符数与 2MB 上限截断
    - 裸域名自动补 https；拒绝非 http(s) 协议与本机/内网地址，放行 198.18.0.0/15、2001:2::/48（本地代理 fake-ip，否则所有公网站点都被误拦）
    - fetch_url 注册进 ToolRegistry，登记到 tool_metadata 的 information 领域，并加入 defaults 与全部角色的常驻列表
    - prompt 引导改为按 active_tools 生成：用户发网址用 fetch_url、需要查资料用 web_search，明确禁止把整条 URL 当搜索词
  - **验证**:
    - `tests/unit/test_web_fetch_tool.py 6 项通过`
    - `tests/scripts/tools/verify_web_fetch_tool.py 真实抓取 https://example.icu 成功，返回 1482 字正文（含 hakituo / Autarkia）`
    - `CI 同款 pytest：6112 passed；8 个失败集中在 test_cross_platform_paths.py 与 test_study_daily_library_version.py，相关实现文件无未提交改动，属 HEAD 存量问题`
    - `ruff 与 check_file_sizes 通过，新增文件未超行数上限`
  - **备注**:
    - 站点能否被搜到仍取决于搜索引擎收录；需要读正文的场景现在走 fetch_url，不再依赖收录状态

## 2026-10-22（星期四）

- **Web 端改走 Tailscale 与同源代理，清理停用的 tunnel 域名**
  - **背景**: 网站早已迁到 Cloudflare Pages，tunnel 只剩 Web 与 API 两条路由且长期未启动；DNS 记录仍在，Cloudflare 持续回源失败产生 530。同时 Web 前端从非回环地址访问一直 403：allowed_origins 里只有 localhost 与两个已下线的子域。
  - **根因**:
    - Origin 白名单是静态配置，而局域网 / Tailscale 访问的 Origin 是运行期才知道的动态地址（192.168.x.x、100.x.x.x、MagicDNS 主机名），永远匹配不上 strict_origin 中间件
    - 前端 3000 在非本机访问时仍把 API 指向 http://<host>:8000，既跨域又被 CORS 拦，媒体 cookie 也不会随 img 请求携带
    - tunnel 停用后配置与文档里的两个子域成死值，PORTS.md 还留着早已作废的 5173 映射与 me 子域
  - **修复**:
    - 新增 core/middleware/trusted_origin.py：本机回环 / 私网 / Tailscale（100.64.0.0/10、*.ts.net）判据与 CORS 正则，security.py 的 strict_origin 与 main.py 的 CORSMiddleware 共用同一判据；显式白名单仍是跨公网访问的唯一依据
    - 私网段显式登记而不用 ipaddress.is_private：后者把文档保留段也算私有，会把不可路由的示例网段当成可信来源
    - 前端 config.ts / SettingsView.tsx：dev server 下本机仍直连 8000，非回环访问改走同源 Vite 代理（/api/v1、/health、/static、/output 转发到 127.0.0.1:8000），WebSocket 同样经代理
    - vite.config.ts 的 allowedHosts 由已下线域名改为 .ts.net，覆盖 Tailscale MagicDNS 主机名，IP 访问默认放行
    - 清理 app.yaml 的 allowed_origins、config.ts 的 tunnel 死分支、PORTS.md 与根技术参考的 tunnel 段；Android tunnelUrl 只改注释举例，默认仍为空、组网通道优先
    - 顺手删掉 config.ts 注释里的历史端口字样，verify_frontend_entrypoint_contract.py 由存量红转绿
